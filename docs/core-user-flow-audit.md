> 审计日期：2026-08-06

## 2. 分步走查记录

### 2.1 注册登录

- **用户目标**：开始使用系统，进入自己的工作台。
- **当前入口**：未登录首页 → 「注册账号」/「登录」。
- **实际操作**：用邀请码注册（姓名/邮箱/密码）→ 自动登录 → 进入学生工作台。
- **用户困惑**：无。注册与登录表单直观。
- **流程断点**：无（单次会话内）。
- **页面问题**：登录页品牌区与「账号与角色权限」面板并存，信息密度偏高，但不影响操作。
- **数据问题**：无。
- **涉及文件**：`apps/web/src/App.tsx`（AuthGate）、`apps/web/src/hooks/useAuth.ts`、`apps/api/src/auth/auth.service.ts`。
- **结论**：✅ 正常。但「刷新恢复」不达标，见 P1-01。

### 2.2 首次初始化

- **用户目标**：告诉系统我的目标、现状与可用时间。
- **当前入口**：注册后自动进入初始化向导（4 步）。
- **实际操作**：填目标分/当前分/剩余天数/每日时长/最弱科目 → 生成档案与 7 天计划。
- **用户困惑**：轻微。向导各步没有「为什么收集这些信息」的说明，但每步字段语义清楚。
- **流程断点**：无。
- **页面问题**：无。
- **数据问题**：无。
- **涉及文件**：`apps/web/src/App.tsx`（onboarding 状态机）、`apps/api/src/study/study.service.ts`（`validateOnboardingInput`/`applyDiagnosticProfile`）。
- **结论**：✅ 正常。

### 2.3 快速诊断

- **用户目标**：知道「我现在什么水平、最该补哪里」。
- **当前入口**：首页「生成阶段测评」/ 入职诊断。
- **实际操作**：提交诊断 → 生成「基础/强化/冲刺」阶段、诊断语、7 天计划。
- **用户困惑**：阶段测评与「入学诊断」两个入口并存，用户分不清先做哪个；测评是模拟考试（2 题），诊断是问卷，语义不同但入口接近。
- **流程断点**：无。
- **页面问题**：首页同时有「生成阶段测评」「继续今日学习」「开始专项训练」「立即开始」等多个主按钮，无唯一主操作（P1-02 相关）。
- **数据问题**：无。
- **涉及文件**：`apps/web/src/App.tsx`、`apps/api/src/study/study.controller.ts`（`diagnostics/profile`、`assessments/stage`）。
- **结论**：✅ 功能正常，入口语义需收敛。

### 2.4 查看薄弱知识点

- **用户目标**：确认薄弱点并决定先补哪个。
- **当前入口**：首页「薄弱知识点 TOP5」、报告页、掌握度地图。
- **实际操作**：首页 TOP5（树的遍历应用 60%、进程同步 60%、Cache 69%）→ 错题本 → 报告。
- **用户困惑**：首页「最近错题：暂无近期错题」与实际错题本数据不一致（有 1 条已重做解决的记录），用户会怀疑数据没同步（P2-05）。
- **流程断点**：无。
- **页面问题**：掌握度数字在首页 KPI（平均 69%）、报告（75% 正确率）、冲刺计划等位置口径混用（正确率 vs 掌握度），易误读（P2-06）。
- **数据问题**：无硬伤；薄弱点排序与真实练习记录一致（实测 Cache 从 50%→69%）。
- **涉及文件**：`apps/api/src/study/study.service.ts`（`getMasteryMap`，518-591 行：基于 records+知识图谱实时计算）。
- **结论**：✅ 功能正常，口径一致性待修。

### 2.5 获得今日任务

- **用户目标**：知道「今天具体做什么、做多少、为什么」。
- **当前入口**：首页「今日任务」卡片 / 「今日计划」导航。
- **实际操作**：首页展示 3 个优先任务（高：树的遍历应用；低：Cache、进程同步），每个任务含分钟/题数/原因。
- **用户困惑**（核心）：
  - 点「开始」后只展开手动填写表单（完成题数/正确题数/实际分钟/掌握自评），**不会跳转到练习**，用户不知道做题入口在「题库训练」tab。
  - 「继续今日学习」只滚动到计划区，也不进入练习。
  - 表单与真实练习记录不联动：学生实际做了 Cache 相关练习，今日任务仍是 0/3、进度 0%。
- **流程断点**：计划 → 练习之间存在断层（P1-02）。
- **页面问题**：首页与「今日计划」页重复渲染整套任务卡（含操作按钮）；首页 7 天节奏条每天文案雷同（P2-01）。
- **数据问题**：任务完成只能通过手动表单（`POST /study-tasks/:taskId/complete`），无任何基于练习记录的自动完成逻辑；「剩余约 135 分钟」与冲刺计划「180 分钟/天」不一致（P2-06）。
- **涉及文件**：`apps/web/src/components/TodayPlan.tsx`（`handleStart` 仅调 `startTask`）、`apps/web/src/App.tsx`（`handleContinueToday` 623-627 行仅切 tab+滚动）、`apps/api/src/study/study.service.ts`（`completeStudyTask` 2240-2270 行）。
- **结论**：⚠️ 可用但「开始」语义错误——它标记任务进行中，而不是开始学习（P1-02）。

### 2.6 完成针对性练习

- **用户目标**：把今日任务对应的题做一遍并获得反馈。
- **当前入口**：「题库训练」tab（单题模式）或「开始专项练习」（会话模式）。
- **实际操作**：
  - 单题模式：直接展示 q-001（Cache）→ 作答 → 判题+解析。
  - 会话模式：专项练习 1 题 → 答题卡/标记/自信程度 → 提交 → 确认弹层 → 判题+错因自评。
- **用户困惑**：
  - 单题模式答完 2 题（题库练完）后无「下一题」，只有纯文本「当前题库已练完，可开始专项练习或前往错题本」，**没有任何按钮**；状态行又残留「可继续下一题」（P1-02 / P2-04）。
  - 「回答正确」同时显示「本次错因：时间不足」，正确与错误反馈矛盾（P1-07）。
- **流程断点**：无（练习本身可完成），但完成后「下一步」缺失。
- **页面问题**：移动端「练习」tab 同时渲染仪表盘题库面板与会话工作区，出现两个题目区域（P2-03）。
- **数据问题**（重要）：种子题 q-001 答案与题干矛盾——题干未给出 Cache 行数，选项 1/3/5/7，唯一合理假设 8 行时 29 mod 8 = 5（C），但答案设为 B（3）；选 B 被判「回答正确」，解析却只写「取模」不说明行数（P1-03）。
- **涉及文件**：`apps/web/src/features/practice/PracticePanel.tsx`、`apps/web/src/hooks/usePracticeSession.ts`、`apps/api/src/questions/questions.service.ts`（种子题，22-37 行）、`apps/api/src/study/study.service.ts`（`buildPracticeRecord` 2062-2090 行判题 `selectedAnswer === question.answer`）、`packages/shared/src/learning.ts`（`classifyMistake` 66-92 行）。
- **结论**：⚠️ 可用但反馈可信度与「下一步」均需修。

### 2.7 查看错因解析

- **用户目标**：理解为什么错，并记录原因以便复习。
- **当前入口**：判题结果面板 / 专项练习提交后的错因弹层。
- **实际操作**：答错 → 显示「回答错误+你的答案+正确答案+解析+知识点」→ 专项练习提交后弹「这道题为什么做错了？」→ 系统预选推断原因（如「审题错误」）→ 提交。
- **用户困惑**：轻微。弹层提示「系统判断本次错因为「审题错误」，如符合可直接提交」，与预选行为一致（专项练习流程实测预选正常）。
- **流程断点**：无。
- **页面问题**：无重大。
- **数据问题**：无（`reportWrongReason` 正常写 review schedule，`study.service.ts:1518-1633`）。
- **涉及文件**：`apps/web/src/components/ErrorReasonSelector.tsx`、`apps/api/src/study/study.service.ts`。
- **结论**：✅ 正常（专项练习路径）；重做正确后的复测弹层另见 P1-05。

### 2.8 错题进入复习计划

- **用户目标**：错题被系统记住并排期复习。
- **当前入口**：错因弹层提交后。
- **实际操作**：提交错因 → 状态「已记录本次错因，并安排到次日复习。」→ 错题本出现该题（待复盘）→ 复习计划创建次日到期。
- **用户困惑**：无。
- **流程断点**：无。
- **页面问题**：错题本头部「1 道待复盘」与统计卡「0 待复盘」同屏矛盾，条目徽标却是「已复盘」（P1-06）。
- **数据问题**：错题本「空状态」文案「错题本还是空的」与统计卡「重做解决 1」矛盾（P2-05）。
- **涉及文件**：`apps/api/src/study/study.service.ts`（`reportWrongReason`、`getDueReviews` 1656-1683 行）、错题本前端（`MistakeWorkspace`）。
- **结论**：✅ 数据闭环正常，展示口径需统一。

### 2.9 完成同类题复测（重做/变式）

- **用户目标**：确认错题已真正解决，推动掌握度。
- **当前入口**：错题本条目「重做」。
- **实际操作**（实测复现，桌面+移动均复现）：
  1. 先答任意一题（产生 `practiceAnswerResult`）。
  2. 进入错题本点「重做」。
  3. 页面切到「题库训练」，显示错题题干 + 「错题重做模式」徽标，但**同时渲染上一次作答的结果面板**（题目是 q-001，解析却是 q-002 的 TCP 解析，完全错位）。
  4. 4 个选项全部 `disabled`，点击无反应；`handleSubmitAnswer` 因残留结果直接 return。
- **用户困惑**：以为系统坏了 / 无法继续，只能刷新或换入口。
- **流程断点**：❌ **核心闭环「错题→重做→复测」被卡死**（P0-01）。
- **页面问题**：题目与解析错位展示。
- **数据问题**：无（服务端数据正常，纯前端状态残留）。
- **涉及文件**：`apps/web/src/App.tsx`（`onRedo` 1386-1392 行未清 `practiceAnswerResult`；`handleSubmitAnswer` 502 行 `if (practiceSubmitting || practiceAnswerResult) return`）、`apps/web/src/features/practice/PracticePanel.tsx`（选项 `disabled={submitting || answered}`，`answered = Boolean(answerResult)`）。
- **结论**：❌ P0，必须先修。

### 2.10 查看掌握度和提分趋势

- **用户目标**：确认「学了一周/一场考试后是否提高」。
- **当前入口**：「我的」tab（提分报告）/ 首页掌握度地图。
- **实际操作**：报告结论（数据不足→预计区间）、正确率、薄弱点、7 天冲刺计划、掌握度地图、考试报告。
- **用户困惑**：
  - 首页「预计提分 +12」与报告「预计提分空间 14 分」数字不一致（P2-06）。
  - 模拟考试全对（100%，考点 Cache+TCP），考后复习计划却推荐「树的遍历应用」3 天任务——推荐与考试内容完全错位（P1-04）。
- **流程断点**：无。
- **页面问题**：报告页同时是「我的」tab，标签语义困惑（P2-02）。
- **数据问题**：掌握度由真实练习记录计算（实测 Cache 掌握度随练习变化，✅）；但考后复习推荐在「全对/无失分点」时回退到全局重要性最高的知识点，而非本场考试覆盖考点（P1-04）。
- **涉及文件**：`apps/api/src/study/study.service.ts`（`getMasteryMap` 518-591、`generatePostExamReviewTasksUnlocked` 3525-3600 行：`loss = report.knowledgePointLosses[index] ?? ...`，无失分时落到 `fallbackPoint`）。
- **结论**：✅ 数据真实，推荐相关性待修。

## 3. 横切问题（加载/空状态/错误/刷新）

- **刷新恢复**：❌ 访问令牌过期后刷新即掉线，见 P1-01（移动端高频场景，最伤体验）。
- **加载状态**：✅ 大多有「API 数据 · HH:mm 同步」与 retry 文案；「等待首次保存」等会话状态提示可见。
- **空状态**：⚠️ 文案与数据矛盾——错题本「还是空的」但统计卡有「重做解决 1」；首页「暂无近期错题」与错题本数据不一致（P2-05）。
- **错误状态**：✅ 有显式错误文案（「加载失败，请重试」），无静默回退 Mock。
- **状态文案**：⚠️ 多条 `task-status` 并存且互相矛盾（「可继续下一题」+「当前题库已练完」），用户无法区分当前真实状态（P2-04）。

## 4. 数据与口径问题汇总

1. 种子题 q-001 答案与题干矛盾、题干缺 Cache 行数（P1-03，数据正确性）。
2. 「待复盘」口径在首页 KPI / 错题本头部 / 统计卡 / 条目徽标四处不一致（P1-06）。
3. 计划任务进度与实际练习记录不联动（仅手动表单可完成）（P1-02）。
4. 考后复习推荐与考试内容错位（P1-04）。
5. 正确率/掌握度/预计提分在首页与报告间数字不一致（P2-06）。
