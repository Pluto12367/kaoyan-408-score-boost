# 06 面试讲解

## 1. 项目一句话介绍

这是一个面向计算机考研 408 的个性化提分系统，围绕知识体系、题库、错题、学习计划、掌握度和测评报告，帮助学生完成从诊断到复习的完整学习闭环。

## 2. 30 秒版本

我做的是一个 408 考研提分系统，不是单纯刷题网站。学生注册后先做入学诊断，系统会根据目标分、当前分、剩余天数和薄弱科目生成学习计划。学生每天进入系统后，可以看到今日任务，完成知识学习、题库训练和错题复盘。每次答题都会生成练习记录，系统会根据正确率、用时和错因更新错题本、复习计划、掌握度和提分报告。

技术上前端使用 React + TypeScript + Vite，后端使用 NestJS + Prisma + PostgreSQL，核心判题、错因和计划算法放在 shared 包中，保证前后端口径一致。系统还支持题库导入、教师学情查看、管理员审核和 Docker Compose 部署。

## 3. 2 分钟版本

这个项目的产品目标是解决 408 学生备考中的几个核心问题：不知道哪里薄弱、不知道为什么错、不知道下一步学什么，也不知道自己有没有提高。

所以我把系统设计成一个学习闭环：

```text
注册登录 → 入学诊断 → 学习计划 → 今日任务 → 做题 → 解析 → 错因 → 错题复盘 → 掌握度 → 阶段测评 → 报告 → 下一步计划
```

前端是 React + TypeScript + Vite，采用单页工作台模式，用 `RoleSection` 控制学生、教师、管理员不同页面。学生端有首页、题库、知识图谱、错题、测试几个核心入口。数据层通过 hooks 加载 dashboard、掌握度、错题、推荐练习等资源。

后端是 NestJS，主要模块包括认证、题库、学习、今日提分。认证使用自研 HMAC-SHA256 JWT 和一次性 refresh token；权限通过 RoleGuard 控制，学生只能访问自己的数据，教师只能访问授权学生，管理员访问全量管理数据。

数据库使用 PostgreSQL + Prisma。核心表包括 User、Question、KnowledgePoint、KnowledgeNode、PracticeRecord、StudyPlan、StudyTask、ReviewSchedule、LearningSession 等。每次学生答题都会写入 PracticeRecord，答错会进入错题和复习计划，同时影响掌握度和后续推荐。

我认为项目最大的亮点是它不只记录刷题结果，而是把答题行为转化成学习决策：错题复盘、间隔复习、知识点掌握度、今日任务和阶段报告都串在一起。

## 4. 架构怎么讲

可以按三层讲：

### 前端层

- React 单页应用。
- `App.tsx` 是主容器。
- `StudentSections` 组合学生学习页面。
- `authenticatedFetch` 负责 token 注入和自动刷新。
- heavy modules 使用 `lazy + Suspense` 按需加载。

### 后端层

- NestJS 模块化。
- `AuthModule` 处理账号和会话。
- `QuestionsModule` 处理题库和导入。
- `StudyModule` 处理学习闭环。
- `ScoreCenterModule` 处理今日提分和知识节点能力。
- `RoleGuard` 做权限校验。

### 数据层

- PostgreSQL 存用户、题库、知识点、练习记录、计划、错题、复习、测评和导入任务。
- Prisma 管理 schema、迁移和类型。
- `packages/shared` 存前后端共享的领域规则。

## 5. 最值得讲的 5 个亮点

### 5.1 完整学习闭环

普通刷题网站只解决“做题”，这个系统把做题结果继续流向：

- 错题本。
- 错因分析。
- 复习计划。
- 掌握度。
- 推荐练习。
- 阶段报告。
- 下一步计划。

面试表达：

> 我不是把题库作为终点，而是把题库作为学习数据采集入口。真正的产品价值在后面的复盘和推荐。

### 5.2 权限和数据隔离

学生、教师、管理员三类角色的数据权限不同：

- 学生只能看自己。
- 教师只能看被授权学生。
- 管理员可以管理全局。

在 `StudyController` 中，查询学生数据时通过 `resolveUserId` 和 `assertAccess` 做统一控制。

面试表达：

> 我没有让前端传什么 userId 就查什么 userId，而是在后端统一用当前登录用户做数据访问判断，避免越权。

### 5.3 练习会话与断点恢复

`LearningSession` 保存：

- 题目快照。
- 当前题号。
- 用户答案。
- 标记题目。
- revision。
- 活跃时间。

这样学生刷新页面或中途退出后，可以恢复答题。题目快照也避免题库更新影响历史考试。

### 5.4 知识图谱与掌握度

系统既有粗粒度 `KnowledgePoint`，也有全量原子节点 `KnowledgeNode`。两者通过 `KnowledgePointNodeMap` 桥接。

这让系统能兼容历史题库，同时升级到更细的 408 知识图谱、真题命中和今日提分。

### 5.5 前后端共享领域逻辑

判题、错因、掌握度、计划等规则放在 `packages/shared`，避免前后端重复实现。

面试表达：

> 教育产品最怕前端显示和后端计算口径不一致，所以我把无副作用的领域规则抽到 shared 包中，通过测试保证稳定。

## 6. 常见面试问题与回答

### Q1：这个项目和普通刷题系统有什么区别？

普通刷题系统重点是题目列表、提交答案和解析。这个系统重点是提分闭环：每次做题都会变成学习数据，影响错题复盘、复习计划、掌握度、推荐题组和学习报告。

### Q2：你项目里最复杂的业务是什么？

最复杂的是学习闭环编排。因为一次答题会影响多条链路：练习记录、错题、复习调度、掌握度、今日计划和报告。这里要保证数据一致，也要保证学生看到的下一步动作是合理的。

### Q3：为什么不用第三方登录/JWT 库？

当前项目选择自研 HMAC-SHA256 JWT 和 scrypt 密码，是为了减少依赖并完全掌控会话逻辑。refresh token 是一次性轮换并 hash 入库，安全上比简单长期 token 更稳。

如果是大型商业项目，也可以替换为成熟认证服务，但当前实现能体现对认证机制的理解。

### Q4：如何防止学生越权查看别人数据？

后端不信任客户端传入的 userId。学生接口通过 `@CurrentUser()` 获取当前用户，并在 `resolveUserId` 中判断：学生只能访问自己，教师要经过授权关系，管理员才可以访问其他用户。

### Q5：为什么题目要有 QuestionFamily？

题目会被修订。如果直接覆盖题目，会影响历史答题记录和内容追溯。用 `QuestionFamily + versionNumber + isCurrent` 可以保留版本历史，同时让当前题库使用最新版本。

### Q6：错题本是怎么实现的？

错题本不是用户手动添加的，而是从 `PracticeRecord` 中答错记录聚合出来。答错后系统会创建或更新 `ReviewSchedule`，学生复盘时生成 `ReviewAttempt`，同时可以记录错因和笔记。

### Q7：为什么需要 questionSnapshot？

考试或练习开始后，题库可能被教师修改。如果不保存快照，学生提交时看到的题目可能已经变了。`LearningSession.questionSnapshot` 保证一次会话内题目稳定，也方便历史报告复盘。

### Q8：你如何设计 AI 能力？

当前 AI 能力主要是 AI 答疑和追问，后端提示词会带题目、标准解析、知识点、错因和最近错题上下文。未来可以扩展 RAG 知识助手、AI 错题诊断、AI 学习规划和 AI 出题，但前提是必须基于真实知识库、题库和用户学习数据，不能做无数据支撑的“假 AI”。

### Q9：项目目前最大技术债是什么？

主要是两个：

- `StudyService` 和 `App.tsx` 偏大，需要继续按业务域拆分。
- 掌握度存在粗粒度 `KnowledgePoint` 和原子 `KnowledgeNode` 两套口径，需要逐步统一。

### Q10：如果继续优化 30 天，你会做什么？

优先级是：

1. 稳定学生核心闭环：登录、今日计划、做题、错题、知识图谱、报告。
2. 加强 E2E 测试，确保线上核心路径不回归。
3. 收敛掌握度口径，让报告、推荐、计划都基于同一套知识状态。
4. 拆分 `StudyService` 和 `App.tsx`，提升可维护性。
5. 引入更真实的 AI 学习规划和错题诊断。

## 7. 简历写法

可以这样写：

```text
计算机考研 408 个性化提分系统
- 基于 React + TypeScript + NestJS + Prisma + PostgreSQL 构建 408 学习闭环系统，覆盖入学诊断、学习计划、题库训练、错题复盘、阶段测评和提分报告。
- 设计 PracticeRecord、ReviewSchedule、LearningSession、KnowledgeNode 等核心模型，将答题行为转化为错题复习、掌握度更新和推荐计划。
- 实现自研 JWT + refresh token 轮换认证，结合角色权限控制学生、教师、管理员的数据访问边界。
- 抽象 packages/shared 共享判题、错因分类、学习计划和掌握度等领域规则，降低前后端逻辑不一致风险。
- 支持题库文档导入、内容指纹去重、候选审核和 Docker Compose 腾讯云部署。
```

## 8. 面试讲解顺序

建议按这个顺序讲：

1. 先讲产品目标：408 提分，不是普通刷题。
2. 再讲核心闭环：诊断、计划、做题、错题、复习、报告。
3. 然后讲技术架构：React + NestJS + Prisma + PostgreSQL + shared。
4. 重点讲 2-3 个亮点：权限、会话、知识图谱、错题复盘。
5. 主动讲不足：大文件、掌握度口径、E2E 测试。
6. 最后讲未来优化：AI、测试、拆分、商业化。
