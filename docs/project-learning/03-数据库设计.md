# 03 数据库设计

## 1. 数据库与 ORM

当前数据库技术栈：

- PostgreSQL 16。
- Prisma 5。
- Schema 文件：`prisma/schema.prisma`。
- 生产迁移：`prisma migrate deploy --schema prisma/schema.prisma`。

数据库围绕 5 类数据设计：

1. 账号与权限。
2. 题库与知识体系。
3. 学习行为与练习记录。
4. 学习计划与复习调度。
5. 导入、运营和审计。

## 2. 账号与权限模型

核心表：

- `User`
- `RefreshToken`
- `InvitationCode`
- `InvitationRedemption`
- `TeacherStudentAuthorization`
- `AuditEvent`
- `OperationLog`

`User` 是全局用户表，通过 `role` 区分：

- `STUDENT`
- `TEACHER`
- `ADMIN`

权限设计要点：

- 学生只能访问自己的学习数据。
- 教师只能访问被授权学生的数据。
- 管理员可以访问全量管理数据。
- refresh token 一次性轮换，hash 存储在 `RefreshToken`。
- 邀请码不明文入库，只保存 `codeHash` 和 `codePrefix`。

## 3. 题库模型

核心表：

- `QuestionFamily`
- `Question`
- `QuestionKnowledgePoint`
- `QuestionKnowledgeNodeTag`

设计关系：

```text
QuestionFamily 1 - N Question
Question N - M KnowledgePoint
Question N - M KnowledgeNode
```

关键字段：

- `Question.familyId`：题目版本族。
- `Question.versionNumber`：题目版本号。
- `Question.isCurrent`：当前生效版本。
- `Question.contentFingerprint`：内容指纹，用于去重。
- `Question.options`：选项数组。
- `Question.answer`：标准答案。
- `Question.analysis`：标准解析。
- `Question.expectedTimeSec`：预期作答时间。

版本族设计让系统可以支持题目修订，而不是直接覆盖历史题目。

## 4. 知识体系模型

系统存在两套知识抽象：

### 4.1 KnowledgePoint

`KnowledgePoint` 是传统粗粒度知识点，字段包括：

- `subject`
- `chapter`
- `title`
- `importance`
- `frequency`
- `prerequisites`

它主要服务：

- 题目绑定。
- 练习记录。
- 薄弱点报告。
- 传统学习计划。

### 4.2 KnowledgeNode

`KnowledgeNode` 是 408 全量知识树节点，字段包括：

- `parentId`
- `subject`
- `nodeType`
- `name`
- `importance`
- `difficulty`
- `syllabusVersion`
- `isActive`

它主要服务：

- 408 知识图谱。
- 今日提分引擎。
- 原子节点掌握度。
- 真题命中证据。
- 节点闯关。

### 4.3 桥接关系

`KnowledgePointNodeMap` 用于把粗粒度 `KnowledgePoint` 映射到全量 `KnowledgeNode`。

```text
KnowledgePoint N - M KnowledgeNode
```

这个桥接层解决了历史业务与新知识图谱之间的兼容问题。

## 5. 练习与错题模型

核心表：

- `PracticeRecord`
- `WrongQuestionReview`
- `ReviewSchedule`
- `ReviewAttempt`

`PracticeRecord` 是学习数据的底座。每次答题都会形成记录：

- `userId`
- `questionId`
- `knowledgePointId`
- `knowledgePointIds`
- `selectedAnswer`
- `correct`
- `timeSpentSec`
- `expectedTimeSec`
- `mistakeReason`
- `sessionId`
- `confidence`
- `usedHint`
- `answerModified`
- `variantQuestionId`

错题数据的来源不是单独建“错题表”，而是基于 `PracticeRecord.correct = false` 推导，再用复习表记录复盘状态。

复习调度：

- `ReviewSchedule`：某用户某题的当前复习计划。
- `ReviewAttempt`：每一次复习尝试。
- `WrongQuestionReview`：错题是否已复盘、何时复盘。

## 6. 学习计划模型

核心表：

- `StudyPlan`
- `StudyTask`
- `StudyTaskCompletion`

关系：

```text
User 1 - N StudyPlan
StudyPlan 1 - N StudyTask
User 1 - N StudyTaskCompletion
```

`StudyPlan` 表示一轮学习计划，包含：

- 阶段。
- 目标分。
- 剩余天数。
- 每日学习时长。
- 目标考试日期。
- 是否 stale。

`StudyTask` 表示具体任务，包含：

- 知识点或知识节点。
- 推荐动作。
- 推荐原因。
- 预计分钟数。
- 题目数量。
- 计划日期。
- 优先级。
- 当前状态。

`StudyTaskCompletion` 记录学生手动完成任务时填入的真实数据，例如做题数、正确数、用时和自评。

## 7. 会话与考试模型

核心表：

- `LearningSession`
- `AssessmentHistoryItem`
- `Paper`
- `ExamReviewPlan`

`LearningSession` 支持：

- 练习会话。
- 阶段测评。
- 模拟考试。
- 断点恢复。
- 自动保存。
- 题目快照。

关键字段：

- `questionIds`
- `questionSnapshot`
- `answers`
- `markedQuestions`
- `currentIndex`
- `revision`
- `totalActiveMs`
- `completed`
- `submittedAt`

`AssessmentHistoryItem` 记录阶段测评或考试历史结果。

`ExamReviewPlan` 根据考试结果生成考后复习计划，并和 `LearningSession` 一对一关联。

## 8. 今日提分与掌握度模型

核心表：

- `UserKnowledgeMastery`
- `UserMasterySnapshot`
- `UserNodeQuest`
- `KnowledgeFrequencySnapshot`
- `ExamPaper`
- `ExamQuestion`
- `ExamQuestionKnowledgeTag`

`UserKnowledgeMastery` 保存学生在原子知识节点上的掌握度：

- `mastery`
- `accuracy`
- `recentAccuracy`
- `attempts`
- `correctCount`
- `wrongCount`
- `retention`
- `stabilityDays`
- `nextReviewAt`
- `confidence`

`UserMasterySnapshot` 保存每日掌握度快照，用于趋势图。

`UserNodeQuest` 保存节点闯关里程碑。

`KnowledgeFrequencySnapshot` 保存知识点考频证据，如近 3 年频率、近 5 年频率、趋势方向和证据置信度。

## 9. 题库导入模型

核心表：

- `QuestionImportBatch`
- `QuestionImportJob`
- `QuestionImportCandidate`
- `QuestionImportAsset`
- `QuestionImportConfirmation`

流程：

```text
上传 PDF/XLSX/CSV
  ↓
QuestionImportBatch
  ↓
拆分任务 QuestionImportJob
  ↓
解析候选题 QuestionImportCandidate
  ↓
人工审核与去重
  ↓
确认入库 QuestionImportConfirmation
  ↓
生成 Question / QuestionFamily / QuestionKnowledgePoint
```

导入体系的重点是：

- 文件私有存储。
- 解析任务可重试。
- 内容指纹去重。
- 候选题人工审核。
- 审核确认幂等。

## 10. 数据库设计亮点

- 用户、题库、知识体系、学习行为、计划复习彼此关联，支撑完整提分闭环。
- 题目使用版本族设计，方便内容修订。
- 练习会话保存题目快照，避免题库更新影响历史考试。
- refresh token hash 存储，一次性轮换，安全性优于简单长期 token。
- 粗粒度知识点和原子知识节点通过桥接表共存，兼顾历史业务和知识图谱升级。

## 11. 主要风险

- `PracticeRecord` 同时有 `knowledgePointId` 和 `knowledgePointIds`，历史兼容和多知识点统计需要谨慎维护。
- 经典掌握度和节点掌握度仍有口径并存问题。
- 大量业务聚合依赖实时计算和内存缓存，多实例部署时需要继续处理一致性。
- 题库导入模型强大但复杂，对测试和运维要求较高。
