## 1. 项目一句话定位

这是一个**面向计算机考研 408 的个性化提分系统**，不是普通刷题网站。

普通刷题网站解决「做题」这一个动作；本系统把每次答题沉淀成学习数据，驱动「诊断 → 计划 → 做题 → 错题 → 复习 → 测评 → 报告 → 再计划」的完整提分闭环，回答学生最关心的 5 个问题：

1. 我哪里薄弱？
2. 我为什么错？
3. 下一步学什么？
4. 该练哪些题？
5. 我是否真的提高了？

业务范围只聚焦 408 四科：数据结构、计算机组成原理、操作系统、计算机网络。

**目标用户（三角色）：**

| 角色 | 职责 |
|---|---|
| 学生 student | 入学诊断、学习计划、刷题、错题复盘、阶段测评、模拟考试、提分报告、AI 答疑 |
| 教师 teacher | 维护题库与知识点、生成试卷、查看被授权学生的学情（班级分析） |
| 管理员 admin | 账号与邀请码管理、内容审核、题库文档导入、系统配置、运营指标 |

```text
  领域类型 + 判题/错因/计划/掌握度/报告等纯函数 + 408 知识树构建

        部署：Docker Compose（app 容器 + nginx + PostgreSQL + 备份）
```

**架构的三个核心思想：**

1. **前后端分层清晰**：`apps/web`（展示与交互）→ `apps/api`（业务编排与权限）→ `Prisma`（持久化），中间用 REST 沟通。
2. **领域逻辑下沉共享包**：判题、错因、计划、掌握度、报告等「无副作用的业务规则」放在 `packages/shared`，前端展示与后端计算共用同一套口径。
3. **数据闭环回流**：一次作答不是终点，而是错题、复习、掌握度、推荐、报告的数据来源。

## 3. 技术栈说明

### 3.1 技术栈总览（以代码为准）

| 层级 | 技术 | 关键版本 |
|---|---|---|
| Monorepo | npm workspaces（`apps/*`、`packages/*`） | — |
| 前端 | React + TypeScript + Vite | React 18.3 / TS 5.5 / Vite 5.4 |
| 后端 | NestJS + TypeScript（CommonJS） | NestJS 10.4 |
| 数据库 / ORM | PostgreSQL 16 + Prisma | Prisma 5.18 |
| 认证 | 自研 HMAC-SHA256 JWT + scrypt 密码 + 一次性轮换 refresh token | node:crypto |
| 共享领域层 | `packages/shared` 类型 + 纯函数 | TS 5.5 |
| 测试 | Node 内置 `node:test` | 35 个测试文件 |
| 部署 | Docker Compose + nginx + 备份 profile | 腾讯云脚本、Railway 等 |
| 前端增强 | lucide-react（图标）、katex（公式渲染） | — |
| 文档导入 | exceljs、pdf-lib、mineru-open-sdk、腾讯云 OCR | — |
| AI 答疑 | DeepSeek API（`deepseek-client.ts`，需 `AI_API_KEY`） | 无 key 时回退标准解析模板 |

### 3.2 几个关键选型事实（面试会追问）

- **没有用 React Router / Redux / Zustand**：前端是「单页工作台」，用 `RoleSection + visibleSection` + URL hash 管理页面状态。这是有意为之（当前产品形态适合），不是缺失。
- **没有用成熟 JWT 库**：认证是自研 `createHmac('sha256', JWT_SECRET)` 签发的 HS256 JWT，密码用 scrypt 加盐哈希，refresh token 一次性轮换且只存 hash。能讲清 token 机制，但也意味着安全实现需要自己负责。
- **前后端共享 `packages/shared`**：判题、错因、计划、掌握度、知识树等规则只写一遍，前后端各取所需。
- **无数据库也能跑**：`DATABASE_URL` 未配置时，后端用内存数组跑演示数据；**生产环境禁止静默 mock**，`isMockAllowed()` 为 false 时 API 失败会显式报错。

详细选型理由（为什么选这些技术）见 `05-技术选型.md`。

## 4. 前端架构

### 4.1 前端目录结构

```text

├── main.tsx               # React 入口
├── App.tsx                # 主容器：登录态、角色、section、学习动作编排（文件较大）
├── api/
│   ├── client.ts          # authenticatedFetch：token 注入 + 401 自动刷新
│   ├── refreshGate.ts     # refreshSessionOnce 单飞刷新
│   ├── env.ts             # isMockAllowed / isStaticDemoMode
│   └── endpoints/         # auth/onboarding/practice/sessions/exam/review/score-center/...
├── hooks/                 # useAuth、useDashboardOverviewData、useStudentProgressData、
│                          # useStudentLearningData、usePracticeSession、useRoleWorkspaceData
├── layouts/               # RoleNavigation（侧边栏）、RoleLayouts、底部移动导航
├── features/              # 按业务域组织的页面与逻辑
│   ├── student/           # StudentSections、StudentHome、StudentLearningConsole
│   ├── practice/          # PracticePanel、practiceAttemptState、practiceSubmissionGate
│   ├── mistakes/          # MistakeWorkspace 错题复盘
│   ├── knowledge-catalog/ # KnowledgeCatalog 知识图谱
│   ├── assessment/        # StageAssessmentPanel
│   ├── report/            # ReportWorkspace、WeaknessReportPanel
│   ├── today-score-center/# TodaysScoreCenter 今日提分
│   ├── tutor/             # TutorPanel AI 答疑
│   ├── teacher/           # TeacherWorkspace
│   ├── admin/             # AdminWorkspace、question-import/
│   └── auth/              # AccountPanel（登录/注册/改密）
└── components/            # ExamSession、TodayPlan、WrongQuestionDetail、ErrorReasonSelector 等
```

### 4.2 状态与导航模型

- **无路由库、无全局状态库**：`App.tsx` 通过 `useState`/`useMemo`/`useEffect` 持有全局学习状态，`useRoleSectionNavigation` 负责从 URL hash 读取当前 section、监听 `hashchange`（支持浏览器前进后退）、角色切换时重置默认 section，并把旧入口（如 `plan`、`score-center`、`report`）归一化到新入口。
- **角色分区**（`RoleNavigation.tsx`）：
  - 学生：`dashboard`(首页)、`question`(题库)、`knowledge-catalog`(知识)、`wrong-book`(错题)、`test`(测试)；底部导航适配移动端。
  - 教师：`teacher`(题库与班级)、`report`(学情报告)、`ai`(AI 辅助)。
  - 管理员：`admin`(数据看板)、`review`(内容审核)、`config`(系统配置)、`teacher`(教研管理)、`question-import`(题库文档导入)。
- **重型模块懒加载**：`ExamSession`、`KnowledgeCatalog`、`ReportWorkspace`、`AdminWorkspace`、`TeacherWorkspace`、`TodayPlan` 等使用 `lazy + Suspense`，配合 `sectionFallback` 兜底。
- **数据 hooks**：`useDashboardOverviewData`（首页总览）、`useStudentProgressData`（掌握度/冲刺/画像）、`useStudentLearningData`（推荐题组/错题摘要/评估历史）、`useRoleWorkspaceData`（教师/管理端资源）。每个资源都带 `{ data, state, error, lastSyncAt, refresh }` 结构，页面通过 `ModuleResourceState`/`ApiStateIndicator` 统一呈现加载、错误、重试。
- **提交防抖与防重**：`practiceSubmissionGate` 用 token 机制保证一次作答只有一个提交生效，避免快速连点产生脏数据。

### 4.3 认证请求层（authenticatedFetch）

`apps/web/src/api/client.ts` 是整个前端请求的基础设施：

```text
发请求 → 自动加 Authorization: Bearer <accessToken>
       → 收到 401？
           → 有 refreshToken → refreshSessionOnce()（并发单飞，只允许一个刷新请求）
           → 刷新成功 → 用新 token 重试原请求
           → 刷新失败 → 仅当没有其他并发请求替换会话时才清登录态
```

刷新逻辑的关键是 `refreshGate`：因为 refresh token 是一次性轮换的，多个并发请求同时刷新会互相消耗，所以用「单飞」保证只有一个请求去换新 token，其余请求等待并复用结果。

### 4.4 前端几个值得讲的设计

- **学习模式/考试模式复用 `ExamSession`**：专项练习、阶段测评、模拟考试共用一套答题会话组件，通过 `sessionType` 区分，支持学习模式（每题即时核对）与训练模式（整卷计时）。
- **答题计时**：用 `document.visibilitychange` 暂停/恢复计时，页面切后台不计时，保证 `timeSpentSec` 反映真实作答时间。
- **做题中途刷新可恢复**：`ResumeSessionBanner` + `usePracticeSession` 从后端拉取未提交会话继续作答。
- **生产与演示双模式**：`isStaticDemoMode()`（github.io 无 API）走本地 mock 工厂；生产环境禁止静默 mock，失败必须显式展示错误。

## 5. 后端架构

### 5.1 模块划分

`apps/api/src/app.module.ts`：

```text
AppModule
├── ThrottlerModule       # 全局限流 60 次/分钟（APP_GUARD 注册 ThrottlerGuard）
├── PrismaModule          # 数据库访问基础设施
├── OperationsModule      # OperationLog 请求日志、AuditEvent 审计
├── AuthModule            # 注册/登录/刷新/登出/改密/邀请码/管理账号
├── QuestionsModule       # 题库 CRUD、题库文档导入、候选审核、AI 变式题
├── StudyModule           # 学习闭环核心（StudyController + StudyService + Repositories）
└── ScoreCenterModule     # 今日提分、知识节点掌握度、节点闯关
```

`main.ts` 全局配置：

- `ValidationPipe({ whitelist: true, transform: true })`：DTO 校验 + 自动类型转换。
- 请求日志中间件：每个请求生成 `x-request-id`，记录 method/path/status/duration，异步写入 `OperationLog`（不记录请求体）。
- CORS：生产读 `WEB_ORIGIN` 环境变量，开发默认 localhost:5173/4173。
- 生产环境启动前做环境安全检查（`validatePublicEnvironment`），不满足直接退出。

### 5.2 权限模型（后端可信的边界）

核心原则：**后端不信任客户端传入的 userId**。

- `RoleGuard` + `@Roles('student','teacher','admin')`：接口级角色校验。
- `@CurrentUser()`：从 token 解析当前用户，学生接口强制用当前用户 id。
- `StudyController` 中的 `resolveUserId` / `assertAccess`：学生只能访问自己，教师只能访问**已授权**学生（`TeacherStudentAuthorization`），管理员可以访问全量。
- refresh token 只存 `tokenHash`，一次性轮换，防重放。

### 5.3 分层：Controller → Service → Repository

```text
StudyController（路由+参数+权限注解，薄）
        │
        ▼
StudyService（业务编排：判题、计划、错题、报告…… 核心业务层）
        │
        ▼
Repository 层（Prisma 细节隔离，支持 DB / 无 DB 双模式）
        │
        ▼
PrismaService → PostgreSQL
```

Repository 示例：`PracticeRecordRepository`、`LearningSessionRepository`、`ReviewScheduleRepository`、`OnboardingPlanRepository`、`AssessmentHistoryRepository` 等。每个 Repository 都有 `enabled = Boolean(process.env.DATABASE_URL)` 设计，无库时切内存数组。

### 5.4 后端接口面（StudyController 主要端点）


## 6. 数据库设计（核心模型地图）

> 表结构、字段、索引的完整细节见 `03-数据库设计.md`。这里只给「模型地图」用于建立全局认知。

Prisma Schema：`prisma/schema.prisma`，**28 个 model，20 个迁移**，PostgreSQL 16。

按业务域分组：

```text
① 账号与权限
   User / RefreshToken / InvitationCode / InvitationRedemption
   TeacherStudentAuthorization / AuditEvent / OperationLog / UserEvent

② 题库与知识体系
   QuestionFamily（题目版本族） / Question（题目）
   QuestionKnowledgePoint（题目-知识点桥接）
   KnowledgePoint（粗粒度知识点）
   KnowledgeNode（408 全量知识树原子节点）
   KnowledgeRelation（节点关系） / KnowledgePointNodeMap（两套体系桥接）
   QuestionKnowledgeNodeTag / ExamQuestionKnowledgeTag（真题命中）
   ExamPaper / ExamQuestion / KnowledgeFrequencySnapshot（考频证据）

③ 学习行为
   PracticeRecord（每次答题的记录，学习数据的底座）
   WrongQuestionReview（错题复盘） / ReviewSchedule（复习计划） / ReviewAttempt（复习尝试）
   LearningSession（练习/测评/考试会话，含 questionSnapshot 快照）
   AssessmentHistoryItem（测评/考试历史） / Paper / ExamReviewPlan（考后复习任务）

④ 计划与进度
   StudyPlan（一轮计划） / StudyTask（具体任务） / StudyTaskCompletion（任务完成）
   UserKnowledgeMastery（节点掌握度） / UserMasterySnapshot（每日快照）
   UserNodeQuest（节点闯关里程碑）

⑤ 导入与运营
   QuestionImportBatch / QuestionImportJob / QuestionImportCandidate
   QuestionImportAsset / QuestionImportConfirmation
   SystemConfig / FeedbackSubmission / AiTutorLog / RuntimeState
```

几个关键设计（面试常问）：

1. **错题不是独立表**：错题 = `PracticeRecord.correct=false` 推导 + `ReviewSchedule` 调度 + `WrongQuestionReview` 复盘状态。
2. **题目有版本族**：`QuestionFamily + versionNumber + isCurrent + contentFingerprint`，修订题目不覆盖历史。
3. **会话有题目快照**：`LearningSession.questionSnapshot`，保证考试中途题库更新不影响本次作答与历史报告。
4. **两套知识体系并存**：`KnowledgePoint`（传统粗粒度）与 `KnowledgeNode`（原子节点）通过 `KnowledgePointNodeMap` 桥接，兼顾历史题库与知识图谱升级。

## 7. 核心业务模块

### 7.1 认证与账号（AuthModule）

- 邮箱 + 密码 + 邀请码注册；`InvitationCode` 只存 `codeHash`，`InvitationRedemption` 记录核销。
- 登录签发 `accessToken`（HMAC-SHA256 JWT，短期）+ `refreshToken`（随机 48 字节，一次性轮换，DB 存 hash，30 天）。
- 管理员可创建内部账号、临时密码、管理试听状态（`trialStatus`）、启停账号。

### 7.2 题库与内容导入（QuestionsModule）

- 题库 CRUD、知识点维护、候选审核队列（review queue）、AI 变式题生成（`ai-variant.service`）。
- 文档导入流水线：上传 PDF/XLSX/CSV → `QuestionImportBatch` → 拆 `QuestionImportJob` 解析（PDF 走 MinerU/腾讯云 OCR）→ `QuestionImportCandidate` → 人工审核 + 指纹去重 → 确认入库生成 `Question/QuestionFamily/QuestionKnowledgePoint`。
- 内容底座：`starter-320-questions.csv` 320 道自编题 + 16 个知识点（每科 4 个）。

### 7.3 学习闭环（StudyModule，核心）

一次答题的完整业务链（详见 `02-业务流程.md`）：

```text
提交答案 → 判题（shared 纯函数）→ 错因初步分类（classifyMistake）
        → 写入 PracticeRecord
        → 答错 → 创建/更新 ReviewSchedule（1/3/7/14 天）
        → 影响掌握度 / 薄弱点 / 推荐题组 / 今日计划
        → 阶段测评 / 模拟考试 → 报告 → 考后复习任务
```

### 7.4 知识图谱与今日提分（ScoreCenterModule）

- 408 全量知识树（`KnowledgeNode`，四科），前端 `KnowledgeCatalog` 可视化，节点带考频证据（近 3/5 年频率、趋势、置信度）、掌握度着色、真题命中证据。
- `UserKnowledgeMastery` 持久化节点级掌握度（mastery/accuracy/attempts/retention/nextReviewAt），`UserMasterySnapshot` 记录每日快照画趋势。
- 节点闯关：`UserNodeQuest` 记录正确率 >= 60% 通关。
- 今日提分：`TodaysScoreCenter` 基于薄弱节点给出推荐动作与理由（`WhyRecommendedDrawer` 展示证据）。

### 7.5 AI 答疑（StudyModule 内）

- `POST /ai/tutor-reply`：携带题目、标准解析、知识点、错因、最近错题上下文，DeepSeek 四层分层提示拆解。
- `POST /ai/follow-up`：自由追问 + 5 类快捷追问，返回复习卡片（`AiFollowUp.reviewCards`）。
- 真实调用写 `AiTutorLog`；未配置 `AI_API_KEY` 时回退标准解析模板（`ai-tutor.service.ts`）。

### 7.6 教师与管理端

- 教师：题库维护、生成试卷、班级分析（授权学生聚合学情）。
- 管理员：运营指标（`beta-metrics.service.ts`）、用户/邀请码/审核/配置管理、题库导入工作台、推荐策略参数（阶段测评题数、每日目标题数、速度风险系数）。

## 8. 一次完整用户操作的数据流（以「学生做一道题」为例）

这是面试时最能体现「我对系统有整体理解」的示例，建议背熟。

```text
① 学生点击选项「A」
        │
② 前端 PracticePanel 调用 handleSubmitAnswer
        │   computeStageReport 计时（readPracticeElapsedSec：含页面后台暂停逻辑）
        ▼
③ apps/web → POST /practice-records
        │   body: { questionId, knowledgePointId, selectedAnswer, timeSpentSec, variantQuestionId? }
        │   authenticatedFetch 自动带 Bearer token（过期则自动刷新并重试）
        ▼
④ StudyController.createPracticeRecord
        │   @CurrentUser() 取 userId —— 客户端传的 userId 一律忽略
        ▼
⑤ StudyService.createPracticeRecord
        │   ┌─────────────────────────────────────────────┐
        │   │ 1. 判题：正确/错误（shared 纯函数）            │
        │   │ 2. 错因初步分类：用时偏慢/蒙题/概念混淆等        │
        │   │ 3. 写入 PracticeRecord（答错则 correct=false） │
        │   │ 4. 答错 → 创建/更新 ReviewSchedule（1/3/7/14）│
        │   │ 5. 更新薄弱点统计、影响掌握度、推荐、今日计划    │
        │   └─────────────────────────────────────────────┘
        ▼
⑥ 返回 PracticeAnswerResult：{ correct, correctAnswer, analysis, knowledgePointTitle, mistakeReason }
        ▼
⑦ 前端 setPracticeAnswerResult
        │   答错 → 弹出 ErrorReasonSelector 错因自评（异步写入 mistakeReason）
        │   答对 → 提示继续下一题
        ▼
⑧ 后台并行刷新（Promise.allSettled）：
        dashboard/overview → 今日计划 → 学习提醒 → 冲刺计划 → 掌握度 → 错题摘要
        ▼
⑨ 学生下次打开首页/错题本/今日计划时，看到这次作答引发的所有变化
```

**这个数据流要讲清的两个重点：**

1. **一次作答 = 一个数据事件**：不只写一条记录，而是联动错题、复习、掌握度、推荐、报告五条链路。
2. **权限边界在后端**：无论前端传什么 userId，后端只认 token 里的当前用户。

变体（更完整的闭环）：如果这次作答属于一场模拟考试，则走 `POST /sessions/practice/start` → 会话自动保存（`/save`，8 秒一次 + keepalive）→ 提交 `/submit` → 从 `questionSnapshot` 批量生成 PracticeRecord → `GET /exam/report/:sessionId` 生成考试报告 → `generatePostExamReviewTasks` 生成考后复习任务 → 成绩写入 `AssessmentHistoryItem` 形成趋势。

## 10. 架构评价（面试官视角）

### 优点

1. **学习闭环完整**：做题结果回流到错题、复习、掌握度、推荐、报告，是真正的「提分系统」而非题库。
2. **前后端口径一致**：判题/错因/计划/掌握度/报告规则集中在 `packages/shared`，通过测试保证稳定。
3. **权限设计可信**：后端不信任客户端 userId，学生/教师/管理员三层数据隔离。
4. **会话与快照机制**：断点恢复 + 题目快照，解决刷新丢进度、题库更新影响历史作答两个真实痛点。
5. **内容导入工业化**：PDF/XLSX/CSV 解析 → 候选审核 → 指纹去重 → 确认入库，题库可以持续增长。

### 风险与技术债（主动讲，面试加分）

1. `StudyService`（4000+ 行）和 `App.tsx` 偏大，需要按业务域继续拆分（练习/错题/报告/计划/测评服务）。
2. 掌握度存在 `KnowledgePoint`（经典口径）与 `KnowledgeNode`（原子口径）两套，需要逐步统一。
3. 前端无路由库，适合当前单页工作台，未来若做 SEO/公开页/深层路由需引入路由方案。
4. 前端测试以静态约束 + 纯函数为主，组件测试与 E2E 待补强。
5. 认证自研（HMAC JWT + scrypt + 一次性 refresh token），当前足够，规模化时可评估成熟方案。

## 11. 面试重点：「介绍一下你的项目」怎么答

> 完整话术与追问准备见 `06-面试讲解.md`，这里给「回答框架」。

### 30 秒版（一句话 + 一个闭环 + 一套技术栈）

> 我做的是一个计算机考研 408 个性化提分系统。它不是普通刷题网站，核心是一个学习闭环：学生注册后先做入学诊断，系统根据目标分、当前水平、剩余天数和薄弱科目生成学习计划；每天进入系统看到今日任务，完成做题、错题复盘和阶段测评。每次答题都会生成练习记录，驱动错题本、间隔复习、知识点掌握度、推荐题组和提分报告。
>
> 技术上前端是 React + TypeScript + Vite，后端是 NestJS + Prisma + PostgreSQL，判题、错因、计划这些核心规则放在前后端共享的 `shared` 包里保证口径一致。系统支持学生、教师、管理员三类角色，并且已经用 Docker Compose 部署上线。

### 2 分钟版（按「产品 → 架构 → 亮点 → 不足」四段式）

**第一段 产品目标：** 408 学生备考有三个痛点——不知道哪里薄弱、不知道为什么错、不知道下一步学什么，也看不到自己是否真的提高了。这个系统的目标就是把这 5 个问题都回答掉，所以我把产品设计成一个闭环而不是一个题库。

**第二段 技术架构：** 前端 React 单页工作台，`App.tsx` 管状态编排，`StudentSections` 组合页面，`authenticatedFetch` 统一处理 token 和自动刷新，重型模块懒加载。后端 NestJS 分成 Auth、题库、Study、今日提分四个业务模块，全局有 ValidationPipe 和限流，权限用 RoleGuard + @CurrentUser，学生只能看自己的数据。数据库 PostgreSQL，核心模型包括 User、Question、PracticeRecord、ReviewSchedule、LearningSession、KnowledgeNode 等。

**第三段 讲 2-3 个亮点：** 我最想讲的是「一次作答不是一个终点，而是一个数据事件」——答错一道题会自动进入错题本、生成 1/3/7/14 天的复习计划、更新掌握度、影响明天的推荐练习，最后反映在报告里。其次是会话与题目快照机制，考试中途刷新、断网都能恢复，题库更新也不会影响历史作答。还有一个是前后端共享领域规则，判题、错因、计划算法只写一遍。

**第四段 主动讲不足与规划：** 目前 `StudyService` 和 `App.tsx` 偏大，掌握度有两套口径，前端测试还需要补强。如果继续迭代，我会先拆分服务、统一掌握度口径，再补 E2E 测试，然后引入更真实的 AI 学习规划。

### 一页纸架构记忆卡

```text
一句话：408 个性化提分系统 = 学习闭环，不是题库
架构：React SPA → NestJS(4 模块) → Prisma → PostgreSQL，共享规则在 shared 包
角色：学生(闭环主体) / 教师(题库+学情) / 管理员(审核+导入+运营)
闭环：诊断 → 计划 → 做题 → 判题错因 → 错题 → 间隔复习 → 掌握度 → 测评 → 报告 → 再计划
亮点：① 数据闭环回流 ② 权限后端可信 ③ 会话快照断点恢复 ④ shared 口径一致 ⑤ 内容导入工业化
技术债：StudyService/App.tsx 过大、掌握度双口径、前端测试待补
```
