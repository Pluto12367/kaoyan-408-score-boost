# 04 核心代码解析

## 1. 前端入口 App.tsx

核心文件：

- `apps/web/src/main.tsx`
- `apps/web/src/App.tsx`

`App.tsx` 是当前前端主容器，负责：

- 登录态管理。
- 根据角色切换学生、教师、管理员工作区。
- 加载学生学习数据。
- 管理当前 section。
- 处理做题、错题、测评、考试、AI 答疑等动作。
- 组合懒加载页面。

当前 `App.tsx` 的特点：

- 功能完整，但文件较大。
- 通过 hooks 拆出部分数据加载逻辑。
- 通过 `StudentSections` 拆出学生页面组合。
- 通过 `useRoleSectionNavigation` 管理 section/hash/sessionStorage。

## 2. 前端导航核心

文件：

- `apps/web/src/layouts/RoleNavigation.tsx`
- `apps/web/src/features/navigation/useRoleSectionNavigation.ts`

`RoleNavigation.tsx` 定义角色对应的导航项：

- 学生：`dashboard`、`question`、`knowledge-catalog`、`wrong-book`、`test`。
- 教师：`teacher`、`report`、`ai`。
- 管理员：`admin`、`review`、`config`、`teacher`、`question-import`。

`useRoleSectionNavigation` 负责：

- 从 URL hash 读取当前 section。
- 从 sessionStorage 兼容恢复旧 section。
- 将旧入口归一化到新入口。
- 监听 `hashchange` 支持浏览器前进/后退。
- 在角色切换时重置默认 section。

这一层决定了前端虽然没有 React Router，但仍能实现可分享、可恢复的工作台页面状态。

## 3. 学生页面组合 StudentSections

文件：

- `apps/web/src/features/student/StudentSections.tsx`

它接收 `App.tsx` 聚合好的数据和事件回调，根据 `visibleSection` 渲染不同学生模块：

- `dashboard`：学习控制台、学习画像、今日路径。
- `question`：题库练习、薄弱点、推荐资源。
- `wrong-book`：错题复盘工作台。
- `test` / `report`：提分报告工作台。
- `ai`：AI 答疑。

设计价值：

- 把学生端 UI 组合从 `App.tsx` 中拆出来。
- 让 `App.tsx` 更多承担状态编排，`StudentSections` 承担页面选择。
- 保留旧 `report` 兼容入口，避免历史 hash 或存储状态失效。

## 4. API 客户端 authenticatedFetch

文件：

- `apps/web/src/api/client.ts`

核心职责：

1. 从内存中的 `activeAuthSession` 读取 token。
2. 为请求自动添加 `Authorization: Bearer <token>`。
3. 请求遇到 401 时，如果有 refresh token，则尝试刷新会话。
4. 使用 `refreshSessionOnce` 避免多个并发请求重复消费一次性 refresh token。
5. 刷新成功后重试原请求。
6. 刷新失败时，仅在没有其他并发请求替换会话的情况下清理登录态。

这是认证体验的关键代码：用户 access token 过期时，系统可以自动续期，而不是频繁把用户踢回登录页。

## 5. 后端模块装配 AppModule

文件：

- `apps/api/src/app.module.ts`

当前后端模块：

```text
ThrottlerModule
PrismaModule
OperationsModule
AuthModule
QuestionsModule
StudyModule
ScoreCenterModule
```

并通过 `APP_GUARD` 注册全局 `ThrottlerGuard`。

这个文件体现了后端的边界：

- Auth 负责身份。
- Questions 负责题库。
- Study 负责学习闭环。
- ScoreCenter 负责提分推荐和知识节点能力。
- Prisma 作为基础设施。
- Operations 做日志等运维能力。

## 6. StudyController

文件：

- `apps/api/src/study/study.controller.ts`

`StudyController` 是学习业务 API 的门面层，包含大量学生端接口：

- `GET /dashboard/overview`
- `GET /today/plan`
- `POST /practice-records`
- `GET /wrong-questions`
- `GET /wrong-questions/summary`
- `POST /wrong-questions/:questionId/reason`
- `GET /review/due`
- `GET /assessments/stage`
- `POST /assessments/stage/submit`
- `POST /sessions/practice/start`
- `POST /sessions/practice/:sessionId/save`
- `POST /sessions/practice/:sessionId/submit`
- `GET /exam/report/:sessionId`
- `POST /exam/papers/prepare`
- `POST /ai/tutor-reply`
- `POST /ai/follow-up`

安全重点：

- 学生相关接口都使用 `@CurrentUser()`。
- 注释明确写着 userId 不应来自客户端。
- `resolveUserId` 控制学生、教师、管理员的数据访问范围。
- `assertAccess` 用于检查指定学生资料访问权限。

## 7. StudyService

文件：

- `apps/api/src/study/study.service.ts`

`StudyService` 是当前系统最核心的业务编排层，负责：

- 生成 dashboard overview。
- 应用入学诊断。
- 生成学习计划。
- 判题并创建练习记录。
- 维护错题本和复习计划。
- 生成推荐练习。
- 生成阶段测评。
- 提交测评和考试。
- 生成报告。
- 处理教师和管理员聚合数据。
- 调用 AI 答疑。

优点：

- 学习闭环集中在一个服务里，业务理解成本低。
- 调用 repository 层完成持久化。
- 能兼容无数据库演示模式。

风险：

- 文件过大，未来新增业务容易相互影响。
- 需要继续按领域拆分，例如练习服务、错题服务、报告服务、计划服务、测评服务。

## 8. Repository 层

Study 模块下有多类 repository：

- `PracticeRecordRepository`
- `LearningSessionRepository`
- `LearningProgressRepository`
- `LearningProfileRepository`
- `OnboardingPlanRepository`
- `AssessmentHistoryRepository`
- `ReviewScheduleRepository`
- `ExamReviewPlanRepository`
- `FeedbackRepository`
- `TeacherStudentAuthorizationRepository`
- `KnowledgePointRepository`

Repository 的作用：

- 隔离 Prisma 细节。
- 支持有数据库和无数据库两种模式。
- 降低 `StudyService` 直接操作数据库的复杂度。

很多 repository 都有 `enabled = Boolean(process.env.DATABASE_URL)` 的设计。这让项目可以在无数据库环境跑演示数据，但生产环境禁止静默 mock。

## 9. 会话答题核心

相关文件：

- `apps/web/src/components/ExamSession.tsx`
- `apps/web/src/hooks/usePracticeSession.ts`
- `apps/api/src/study/learning-session.repository.ts`
- `prisma/schema.prisma` 的 `LearningSession`

关键机制：

- 创建会话时保存 `questionSnapshot`。
- 前端定期保存答案和当前位置。
- 后端用 `revision` 做乐观并发控制。
- 提交时由会话快照生成练习记录。
- 页面关闭时使用 keepalive 保存。

这个机制解决了考试/练习中途刷新、断网、题库更新导致状态丢失的问题。

## 10. 判题与错因核心

相关文件：

- `packages/shared/src/learning.ts`
- `apps/api/src/study/study.service.ts`
- `apps/web/src/components/ErrorReasonSelector.tsx`

流程：

```text
提交答案
  ↓
根据标准答案判断 correct
  ↓
根据作答行为分类 mistakeReason
  ↓
返回解析和正确答案
  ↓
答错时弹出错因自评
  ↓
写入复习计划和错题详情
```

系统不只记录“对/错”，还记录：

- 用时是否偏慢。
- 是否使用提示。
- 答案是否修改。
- 自信度。
- 自评错因。

这些数据让后续推荐更像学习系统，而不是普通题库。
