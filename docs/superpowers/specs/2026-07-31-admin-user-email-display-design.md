# 管理员用户列表邮箱展示设计

## 背景与目标

真实学生通过邀请码注册后，账号已保存到 PostgreSQL，也能正常登录，但管理员用户列表只展示姓名、角色和试用状态，无法通过登录邮箱识别同名账号。

本次变更让管理员用户列表展示所有角色（学生、教师、管理员）的登录邮箱，同时维持现有权限和数据安全边界。

## 范围

- 管理员专用 `GET /admin/users` 响应为每个用户增加可为空的 `email` 字段。
- PostgreSQL 用户仓储把现有 `User.email` 映射到管理员用户记录。
- 前端管理员用户类型接收该字段，并在用户姓名下展示完整邮箱。
- 没有邮箱的旧账号显示“未设置邮箱”。

本次不增加搜索、排序、邮箱编辑、数据库字段或数据库迁移。

## 权限与隐私

- 邮箱仅通过现有管理员角色保护的 `/admin/users` 返回。
- 学生、教师和公开接口不新增邮箱字段。
- 页面不展示密码哈希、临时密码、刷新令牌或完整邀请码。

## 数据流

1. `AdminUserRepository.list()` 从现有 `User.email` 读取邮箱。
2. `StudyService.getAdminUsers()` 将邮箱映射到管理员用户响应。
3. 前端 `fetchAdminUsers()` 接收响应。
4. `AdminWorkspace` 在每个账号卡片中显示邮箱或空值提示。

## 错误与兼容处理

- `email` 保持可为空，以兼容没有邮箱的旧账号和内存数据。
- 缺少邮箱不会阻止管理员用户列表加载。
- 现有账号状态、试用状态和管理操作保持不变。

## 测试与验收

- 仓储或服务测试证明数据库账号邮箱进入管理员响应。
- UI 测试证明邮箱会显示，空邮箱显示“未设置邮箱”。
- 完整测试套件通过。
- 部署后管理员页面能看到测试学生 `student-test-001@example.com`。
- 学生注册、登录和邀请码单次使用流程继续通过。

## 部署

变更不需要数据库迁移。代码推送到 `codex/deployment-ready` 后，服务器执行快进更新和现有部署脚本重建应用与网关。
