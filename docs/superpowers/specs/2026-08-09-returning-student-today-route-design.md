# 返校学生“今日学习路线”首页优化设计

> 日期：2026-08-09
> 状态：用户已批准体验结构、组件与数据流、异常状态、验收标准和视觉方向
> 范围：学生端“学习总览 → 今日任务 → 练习/复盘”前端体验
> Git 边界：本设计文档不自动提交、推送或创建分支

## 1. 背景

返校学生已有诊断结果与今日计划，但当前学习总览同时突出“继续今日学习”“今日提分”“408知识图谱”、模拟考试、错题和报告等入口。`handleContinueToday()` 只把用户带到今日计划并定位首个未完成任务，用户仍需再次点击才能启动任务。

本轮优化聚焦高频返校场景：学生登录后立刻理解今天的完整学习路线，并用一次点击继续当前任务。该任务独立于 Question Annotation / Retrieval V2，不修改其相关文件。

## 2. 仓库现状

- 前端是 React 单页应用，通过 `RoleSection` 与 URL hash 切换模块，无路由库和状态管理库。
- `StudentLaunchpad` 是学生学习总览；当前首页含多个并列行动入口。
- `GET /today/plan` 已返回 `summary`、`priorityTasks`、`weekProgress`、`reviewDue` 等数据。
- `TodayPlan` 已支持任务开始、完成、延期、改期和计划再平衡。
- `POST /tasks/:id/start` 只把任务标记为 `in_progress`；当前前端不会在成功后自动进入对应训练。
- `TodayPlan.priorityTasks` 已包含 `knowledgePointId`、`mode`、`priority`、`reason`、`status`、`progress` 等启动上下文。
- 题库训练当前从已加载的 `questions` 选择题目；错题页已有知识点筛选，但尚未接收首页启动上下文。
- 生产 API 失败必须显式报错；静态演示与本地 DEV Mock 继续由现有环境门禁控制。

## 3. 目标与成功标准

### 3.1 目标

1. 返校学生无需判断多个并列入口，即可看到今天的任务顺序。
2. 当前可执行任务保持唯一主行动，并能一步进入对应练习或复盘。
3. 保留计划全貌与调整能力，但不让它们争夺主按钮层级。
4. 仅做前端编排与展示优化，不改变推荐、判题、掌握度或计划生成算法。

### 3.2 成功标准

- 学生进入学习总览后，无需滚动即可看到今日路线和当前任务。
- 第一屏最多出现一个高强调主按钮。
- 支持的任务一次点击即可进入对应知识点的练习或复盘。
- 启动失败时不导航、不丢失任务上下文，并提供明确重试。
- 任务完成后刷新计划并展开下一项可执行任务。
- 375px、720px 和桌面宽度无横向溢出、遮挡或双重主按钮。

## 4. 方案比较与选择

### 4.1 方案 A：聚焦主任务

第一屏只放一个大任务卡，其他信息退居下方。行动最集中，但用户不易理解当天完整节奏。

### 4.2 方案 B：双栏驾驶舱

左侧任务、右侧推荐原因和进度。解释充分，但桌面上两栏竞争注意力，移动端重排后层级容易失真。

### 4.3 方案 C：计划时间线（已选）

展示完整今日路线，展开当前可执行任务，后续任务保持紧凑。用户在视觉对比中最终选择方案 C。

最终设计吸收方案 A 的行动聚焦：时间线保留全貌，但第一项可执行任务拥有唯一主按钮。

## 5. 体验设计

### 5.1 第一屏结构

1. 顶部显示问候语与“今天先完成最重要的一件事”。
2. “今日学习路线”标题区显示预计总时长、已完成时长和低强调“调整计划”入口。
3. 时间线按稳定优先级展示任务：
   - 当前任务展开，显示科目、章节、推荐原因、题量、预计时长、进度和主按钮。
   - 后续任务显示顺序、名称、预计时长和状态。
4. 薄弱知识点、最近错题、趋势与模拟考试保留在路线之后，不与主任务并列为强行动。
5. “今日提分”保留为辅助导航，不参与首页任务重新排序。

### 5.2 主按钮文案

- `pending`：开始练习 / 开始复盘。
- `in_progress`：继续练习 / 继续复盘。
- `postponed` 且未到 `nextAvailableAt`：不显示可用主按钮，展示下次可用时间。
- 所有任务完成：展示完成状态，不显示新的强主按钮；可提供低强调“查看报告”或“复习错题”。

### 5.3 任务选择规则

任务选择是前端展示规则，不是新的推荐算法：

1. 排除 `status === 'completed'` 或 `completed === true` 的任务。
2. 可执行状态为 `pending`、`in_progress`，以及已到 `nextAvailableAt` 的 `postponed`。
3. 按“高 → 中 → 低”选择当前任务；同优先级保持服务端原始顺序。
4. 若没有可执行任务但存在延期任务，显示最近可用时间，不猜测替代任务。
5. 若列表为空，进入“今日任务已完成”状态。

## 6. 组件与职责

### 6.1 `TodayLearningRoute`

新增于 `apps/web/src/features/onboarding/TodayLearningRoute.tsx`。

职责：

- 渲染路线标题、进度、时间线和当前任务状态。
- 保证只有一个主按钮。
- 接收数据和事件回调，不直接请求 API、不决定页面路由。

### 6.2 纯函数策略模块

新增 `apps/web/src/features/onboarding/todayLearningRoute.ts`。

职责：

- 选择当前可执行任务。
- 生成稳定的路线展示顺序。
- 根据 `mode` 解析启动目标。
- 生成按钮文案与全完成/延期状态。

策略模块保持无 React、DOM、网络和全局状态依赖，以便通过 `typescript.transpileModule` 在现有 `node:test` 中直接执行行为测试。

### 6.3 `StudentLaunchpad`

职责变化：

- 用 `TodayLearningRoute` 替换当前首页 hero、今日任务 KPI 和会争夺注意力的快捷行动组合。
- 保留下方科目、薄弱点、最近错题、周节奏、趋势和模拟考试模块。
- 不渲染完整 `TodayPlan` 编辑表单；计划调整仍进入独立“今日计划”页面。

### 6.4 `App` 编排

新增一个小范围任务启动处理器，职责仅为：

1. 解析目标并预检对应知识点是否有可用题目或错题。
2. 已知且内容可用的任务调用现有 `startTask(task.id)`。
3. 成功后记录 `task.start` 埋点。
4. 创建短生命周期的任务启动上下文：`taskId`、`knowledgePointId`、`mode`、目标 section。
5. 设置练习或错题知识点范围并导航。
6. 内容缺失或启动失败时把错误返回路线组件，不导航、不改变任务状态。
7. 未知模式不调用 `startTask`，只进入今日计划并定位任务。

业务选择与模式映射必须留在纯函数模块，避免继续扩大 `App.tsx` 的判断逻辑。

### 6.5 练习与错题上下文

- 练习目标：从已加载题库中筛选包含 `task.knowledgePointId` 的题目，当前题与“下一题”只在该临时题池内移动。
- 错题目标：向 `MistakeWorkspace` 传入初始知识点筛选值，并复用现有筛选能力。
- 离开任务训练或主动“重新练习题库”后，清除临时上下文，恢复普通题库行为。
- 不修改题目检索接口、Question Annotation 或 Retrieval V2 文件。

## 7. 启动目标映射

映射依据现有 `mode` 文案，采用明确白名单和安全兜底：

| 任务模式 | 目标 | 行为 |
|---|---|---|
| `基础例题`、`专项训练`、`阶段巩固` | `question` | 进入对应知识点题池 |
| `诊断复盘`、`考后复盘` | `wrong-book` | 打开对应知识点错题筛选 |
| 其他/未知模式 | `plan` | 进入今日计划并定位任务 |

禁止用模糊字符串把未知任务强行映射到练习。新增服务端模式时，前端必须显式扩展白名单和测试。

## 8. 数据流

```text
fetchTodayPlan
    ↓
StudentLaunchpad
    ↓
todayLearningRoute 纯函数选择当前任务和目标
    ↓
TodayLearningRoute 展示路线
    ↓ 点击主按钮
App 启动处理器预检目标内容
    ├─ 内容缺失：留在首页，显示错误，不调用 startTask
    ├─ 未知模式：导航 plan 并定位任务，不调用 startTask
    └─ 内容可用：POST /tasks/:id/start
                    ├─ 失败：留在首页，显示错误与重试
                    └─ 成功：设置知识点上下文 → 导航 question / wrong-book
                                                      ↓
                                              练习或复盘完成
                                                      ↓
                                              refreshTodayPlan
                                                      ↓
                                              展开下一可执行任务
```

不新增 API、Prisma 字段或迁移。数据来源保持为 PostgreSQL/内存双模式下的现有今日计划与题目数据；生产环境不新增 Mock 回退。

## 9. 状态与错误处理

### 9.1 加载与空状态

- 今日计划加载中：显示路线骨架，不显示可能过期的任务按钮。
- 没有计划：保留“完成入学引导和诊断后生成计划”的现有提示。
- 全部完成：展示今日完成状态和低强调后续入口。
- 仅剩未到期延期任务：显示最近可用时间。

### 9.2 启动状态

- 请求期间禁用当前主按钮并显示“正在启动”，防止重复请求。
- 启动失败后恢复按钮，展示可操作错误和重试。
- `startTask` 成功后才导航，避免页面与后端任务状态不一致。

### 9.3 内容缺失

- 练习目标没有匹配题目：明确提示“该知识点暂无可用题目”，不进入全题库或无关推荐题组。
- 复盘目标没有匹配错题：展示该知识点暂无待复盘错题，并提供返回今日计划。
- 未知任务模式：安全进入今日计划并定位任务。

## 10. 响应式与可访问性

- 桌面端使用完整纵向时间线；当前任务展开，后续任务为紧凑行。
- 移动端保持单列，主按钮占满任务内容宽度，元数据可换行。
- 保留现有学生底部导航，不增加新的移动端导航层级。
- 任务按钮使用原生 `button`，启动状态通过可读文本表达，不仅依赖颜色。
- 当前任务和错误提示使用合适的语义与 live status；键盘焦点顺序与视觉顺序一致。
- 不使用复杂或循环动画；若增加轻量状态过渡，必须遵守 `prefers-reduced-motion`。

## 13. 风险与控制

### 13.1 任务模式为自由字符串

风险：服务端新增模式后前端误导航。
控制：白名单映射，未知模式只回到今日计划；测试锁定安全兜底。

### 13.2 对应知识点没有题目或错题

风险：一步启动进入空白或无关内容。
控制：导航前检查本地可用内容；内容缺失时显式错误，不回退全题库。

### 13.3 `App.tsx` 继续膨胀

风险：启动逻辑加入现有大文件后进一步降低可维护性。
控制：选择、映射、文案与状态推导放在纯函数模块；`App` 只保留 API 调用、上下文和导航编排。

### 13.4 与现有首页契约冲突

风险：现有测试要求首页不渲染完整 `TodayPlan`。
控制：新路线是摘要与启动入口，不复制任务编辑表单；调整、延期、改期仍在独立计划页。

## 14. 范围外

- 不合并“今日计划”和“今日提分”的排序或数据模型。
- 不新增推荐分数、推荐理由或 AI 计划生成。
- 不重构整个学生端导航或 `App.tsx`。
- 不改题库检索、Question Annotation、Retrieval V2。
- 不新增状态管理库、路由库或 UI 框架。
- 不将效果图作为运行时产品资源。

## 15. 已批准视觉方向

- 深蓝侧栏、浅色主内容区、白色路线卡片、蓝色唯一主按钮。
- “今日学习路线”是第一屏主要信息结构。
- 当前任务展开；后续任务紧凑排列。
- 进行中任务显示进度和“继续练习/继续复盘”。
- 下方薄弱知识点与最近错题保持低强调，不与当前任务争夺注意力。
