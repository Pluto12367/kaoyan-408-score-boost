# 响应式吸附导航优化设计

> 日期：2026-08-09
> 状态：用户已批准方案 A 及具体设计边界
> 范围：桌面端和平板端通用工作区导航的滚动可见性
> Git 边界：本文档不自动提交、推送或创建分支

## 1. 背景

当前工作区使用两列 `app-shell`：桌面端左侧为 `.sidebar`，右侧为 `.workspace`。侧栏参与整页文档流滚动，因此用户向下阅读较长页面后无法继续看到导航。现有移动端学生导航在 `720px` 及以下已使用固定底部导航，不存在同类问题。

问题同时影响桌面端和 `721–900px` 的平板布局：桌面侧栏会被滚出视口；平板端切换为单列后，完整侧栏位于页面顶部，同样会随页面滚走。

## 2. 目标与非目标

### 2.1 目标

1. 桌面端滚动长页面时，左侧导航始终可达。
2. 平板端滚动长页面时，横向导航始终可达。
3. 保留浏览器原生页面滚动，不引入内容区独立滚动容器。
4. 保持现有角色权限、导航项目、活动项高亮和点击行为不变。
5. 用最小、可测试的前端修改完成优化，避免增加滚动监听和运行时状态。

### 2.2 非目标

- 不让 `.topbar` 吸顶。
- 不重新设计导航信息架构、图标或文案。
- 不修改手机端学生固定底部导航。
- 不修改 API、后端、数据库或数据来源。
- 不修改 Question Annotation、Retrieval V2 及其相关文件。
- 不引入自动收起、滚动方向检测或动画状态机。

## 3. 已比较方案与结论

### 3.1 方案 A：响应式吸附导航（已选）

桌面端让侧栏相对视口吸附；平板端把导航变为顶部横向吸附条；手机端沿用现有底部导航。页面仍由浏览器窗口负责滚动。

优点是符合现有 DOM 和响应式结构，改动集中，浏览器滚动、锚点、弹窗和焦点行为保持自然。

### 3.2 方案 B：固定应用框架

将应用限制为一屏高度，导航固定，右侧内容使用独立滚动容器。应用感更强，但会引入双滚动、滚动恢复、锚点定位、弹窗锁定和触屏手势等额外复杂度。

### 3.3 方案 C：滚动方向自动收起

向下滚动时压缩导航，向上滚动时展开。可节省空间，但行为不够可预测，并增加监听、状态、动画、触屏和无障碍测试成本。

用户在视觉对比中选择方案 A，并批准下面的具体设计。

## 4. 响应式行为

### 4.1 桌面端：宽度大于 900px

- `.sidebar` 使用 `position: sticky` 和 `top: 0`。
- 侧栏与视口同高，优先使用动态视口高度并保留 `100vh` 兼容回退。
- 侧栏设置 `align-self: start`，避免 Grid 默认拉伸影响 sticky。
- 导航内容超过视口高度时，侧栏内部允许纵向滚动。
- `.workspace` 和页面主体继续使用浏览器窗口滚动，不新增 `overflow-y: auto`。

### 4.2 平板端：721–900px

- `app-shell` 保持现有单列结构。
- `.sidebar` 变为 `position: sticky; top: 0` 的紧凑顶部导航区域。
- 大幅品牌标题区在该宽度隐藏，减少吸顶区域高度。
- 角色导航改为单行横向排列；项目过多时允许触屏和鼠标横向滚动，不压缩文字、不换行。
- 当前项目继续使用现有 `.active` 和 `aria-current="page"` 表示。
- 吸顶层级高于普通内容，但低于弹窗、遮罩和系统级浮层。

### 4.3 手机端：宽度不超过 720px

- 学生侧栏继续隐藏，现有 `.bottom-nav` 保持固定在底部。
- 本任务不改变底部导航的五项映射、活动态和安全区内边距。
- 教师和管理员手机端行为保持现状；平板吸顶规则不向 `720px` 以下扩展。

## 5. 结构与职责

预计只涉及以下前端位置：

- `apps/web/src/App.tsx`
  - 为侧栏品牌容器增加明确的样式类，避免依赖 `:first-child` 等脆弱选择器。
- `apps/web/src/layouts/RoleNavigation.tsx`
  - 为通用角色导航增加明确的样式类。
  - 不改变导航数组、角色权限、事件回调或 URL hash 行为。
- `apps/web/src/styles.css`
  - 定义桌面 sticky 侧栏、平板 sticky 横向导航和溢出规则。
  - 保持现有 `<=720px` 学生底部导航规则。
- `test/responsive-sticky-navigation.test.js`（名称可在实现计划中最终确认）
  - 通过仓库现有 `node:test` 契约风格约束结构类、断点和关键 sticky/overflow 规则。

不新增组件状态、Context、hook、事件监听器或第三方依赖。

## 6. 数据流与交互

本任务不改变数据流：

```text
activeSection + sessionUser.role
        ↓
RoleNavigation / StudentBottomNav
        ↓ 点击
onNavigate(section)
        ↓
App 更新 activeSection 与现有 hash
```

仅改变导航容器在不同视口下的布局方式。加载、错误、Mock 门禁、API 调用和业务数据均不受影响。

## 7. 边界与异常状态

- **导航项目超过视口高度：** 桌面侧栏自身纵向滚动，不能截断底部项目。
- **平板导航项目超过宽度：** 横向滚动，不折行成多层吸顶区域。
- **短页面：** sticky 不应制造额外空白或改变页面最小高度。
- **长标题和系统缩放：** 导航按钮保持可聚焦、可滚动到，不用固定像素裁剪文字。
- **键盘操作：** Tab 顺序保持 DOM 顺序；焦点环沿用现有全局规则。
- **弹窗与浮层：** sticky 导航的 `z-index` 不能覆盖对话框、错误原因选择器或考试浮层。
- **打印或无 CSS 环境：** DOM 顺序不变，导航仍位于内容之前。
- **生产环境：** 不增加 Mock 或失败回退行为。

## 8. TDD 与验证

实现必须遵循 RED → GREEN → REFACTOR：

1. 先新增失败契约，验证桌面 sticky、平板 sticky 横向导航、手机底部导航保持不变。
2. 再添加最小结构类和 CSS 规则使测试通过。
3. 仅在测试保护下整理重复媒体查询或选择器。

受影响验证：

```sh
node --test test/responsive-sticky-navigation.test.js
npm run build:web
npm test
```

浏览器视觉验收至少覆盖：

- 桌面宽度：`1440px` 和 `1024px`，滚动到页面中下部后侧栏仍可见。
- 平板宽度：`768px`，滚动后横向导航仍贴顶且可左右滚动。
- 手机宽度：`390px`，学生底部导航仍固定、内容未被遮挡。
- 键盘 Tab 可访问所有导航项，活动项的 `aria-current` 保持正确。
- 页面无新的横向溢出、双滚动条或内容遮挡。

完成后按仓库门禁运行 Web 构建和完整测试；若验证未通过，不得声称完成。

## 10. 验收标准

1. 桌面端向下滚动任意工作区长页面时，左侧导航仍可见并可操作。
2. 桌面导航高度超过视口时，可在侧栏内访问所有项目。
3. 平板端显示单行顶部吸附导航，滚动后仍可见，项目可横向浏览。
4. 手机端学生固定底部导航与现有行为一致。
5. 导航点击、权限过滤、活动项、URL hash 和键盘焦点没有行为回归。
6. 不出现双内容滚动容器、内容遮挡或新增横向页面溢出。
7. 不修改 Question Annotation、Retrieval V2、API、数据库或生产 Mock 门禁。
