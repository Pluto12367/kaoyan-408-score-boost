# 腾讯云公网 IP 体验版设计

## 1. 目标与范围

本阶段把现有前端、NestJS API 和 PostgreSQL 部署到一台腾讯云轻量应用服务器，让测试用户无需安装软件，直接打开公网 IP、输入邀请码并完成注册、登录和学习。

本阶段不购买域名、不提交 ICP 备案、不接入短信、邮件验证或在线支付。题库网页导入属于后续独立阶段，不与本次部署包耦合。

成功标准：

- 用户通过一个公网 IP 入口访问系统。
- 前端和 API 使用同源地址，浏览器不需要跨域配置。
- 无有效邀请码不能注册；有效邀请码可完成注册并自动进入系统。
- PostgreSQL、容器管理端口和应用内部端口不暴露公网。
- 服务器重启后服务自动恢复。
- 管理员能用中文操作手册完成首次部署、升级、备份和恢复。
- 将来购买域名后，只需修改入口配置和环境变量，无需迁移业务数据。

## 2. 方案选择

### 2.1 采用方案

采用腾讯云中国大陆轻量应用服务器，初始规格为 2 核 CPU、2GB 内存、40GB 系统盘。Docker Compose 管理入口、应用和 PostgreSQL 三个服务。

公网入口暂时使用：

```text
http://<服务器公网 IP>
```

入口服务监听 80 端口，提供前端静态资源，并把 `/api/*`、`/health` 请求反向代理到 NestJS API。API 和数据库仅通过 Docker 内部网络通信。

### 2.2 暂不采用的方案

- 免费临时域名或第三方隧道：可能受第三方可用性、国内访问速度和域名生命周期影响。
- 立即购买域名并启用 HTTPS：体验更完整，但与当前“先验证、后购买域名”的约束不符。
- 继续拆分到 Railway、Vercel 等多个平台：会重新引入多平台配置、跨域和日常维护成本。

## 3. 总体架构

```text
学生或管理员浏览器
        |
        | HTTP :80
        v
统一入口容器
  ├─ /              -> React 静态文件
  ├─ /api/*         -> NestJS API 容器
  └─ /health        -> NestJS 健康检查
                            |
                            | Docker 内部网络
                            v
                       PostgreSQL 容器
```

服务职责：

1. `gateway`：公网唯一入口，提供静态文件、反向代理、请求大小限制和安全响应头。
2. `app`：运行数据库迁移并启动 NestJS API；不直接映射宿主机端口。
3. `postgres`：保存账号、邀请码、题库和学习记录；使用 Docker 数据卷持久化，不映射 5432 端口。

所有服务配置 `restart: unless-stopped`，确保服务器或 Docker 重启后自动恢复。

## 4. 构建与配置

生产镜像采用多阶段构建：

1. 构建共享包、React 前端和 NestJS API。
2. 运行阶段只保留生产依赖、API 构建产物、Prisma 文件和迁移文件。
3. 前端构建产物由入口服务提供。

生产配置保存在服务器本地 `.env.production`，该文件不提交 Git。至少包含：

- PostgreSQL 数据库名、用户名和强随机密码。
- `DATABASE_URL`。
- 强随机 `JWT_SECRET`。
- `ALLOW_DEMO_AUTH=false`。
- 公网 IP 对应的 Web 来源配置。
- 备份目录和保留天数。

Compose 配置不得包含真实密码、邀请码、令牌或云服务密钥。示例配置只提供占位符和生成方法。

## 5. 发布与升级

首次部署流程：

1. 创建 Ubuntu 服务器并安装 Docker Engine 与 Compose 插件。
2. 仅在腾讯云防火墙开放 SSH 22 和 HTTP 80；SSH 来源优先限制为管理员当前 IP。
3. 上传版本化发布包和生产环境文件。
4. 构建镜像并启动 PostgreSQL。
5. 执行 `prisma migrate deploy`。
6. 启动应用和入口服务。
7. 检查容器健康状态和 `/health`。
8. 创建首个管理员账号。
9. 在后台生成邀请码，并用全新学生账号执行验收。

升级采用版本化发布目录。新版本通过构建、迁移和健康检查后成为当前版本；应用健康检查失败时恢复上一版本。数据库迁移必须保持向后兼容，应用回滚不自动回滚已经成功执行的数据库迁移。

## 6. 数据与备份

PostgreSQL 数据存储在命名数据卷中，删除或替换应用容器不会删除业务数据。

体验阶段采用两层备份：

- 每天执行一次 PostgreSQL 逻辑备份，保留最近 14 天。
- 每次正式升级前额外执行一次备份并校验文件可读性。

第一版备份先保存在服务器受限目录，并在腾讯云控制台启用每周服务器快照。管理员在邀请真实用户前必须完成一次隔离恢复演练。接入腾讯云对象存储作为后续增强，不阻塞首次公网体验。

备份文件、数据库目录和生产环境文件不得位于 Web 可访问目录。

## 7. 安全边界

- 公网只开放 80 和受限的 22 端口。
- PostgreSQL、NestJS 内部端口和 Docker 管理接口不开放公网。
- 演示认证在生产环境强制关闭。
- 注册继续强制校验邀请码。
- 登录、注册和管理接口沿用现有频率限制与角色权限。
- 日志不得记录密码、完整邀请码、访问令牌或数据库连接密码。
- HTTP 阶段不建议用户复用其他网站密码，并仅邀请少量可信测试用户。

公网 IP 的 HTTP 连接不具备传输加密，这是本阶段已知限制。该入口只用于 10–20 人封闭体验，不宣传为正式公开服务。购买并备案域名后，入口服务切换至 HTTPS，并将 HTTP 自动跳转到 HTTPS。

## 8. 可观测性与故障处理

每个服务配置健康检查。发布验收至少检查：

- 入口首页返回成功。
- `/health` 返回成功且数据库已连接。
- PostgreSQL 容器健康。
- 服务器重启后所有容器自动恢复。
- 磁盘空间足以保留数据库和 14 天备份。

运维手册提供以下常用命令：

- 查看服务状态和最近日志。
- 启动、停止和重启服务。
- 创建、校验和恢复备份。
- 发布新版本和恢复上一版本。

出现应用错误时，先保留数据库卷和备份，再替换应用版本；不得通过删除数据卷处理普通故障。

## 9. 验收流程

首次公网体验前执行：

1. 管理员通过公网 IP 打开登录页。
2. 无邀请码注册被拒绝。
3. 管理员生成一个单次邀请码。
4. 新学生使用邀请码注册并自动登录。
5. 学生退出后可以再次登录。
6. 学生完成一次抽题或学习操作，刷新页面后数据仍存在。
7. 管理员停用该学生，现有会话失效。
8. 管理员恢复账号，学生重新登录成功。
9. 执行数据库备份并在隔离 PostgreSQL 容器中恢复成功。
10. 重启服务器，所有服务恢复且数据不丢失。
11. 分别用手机和桌面浏览器完成注册与登录。

全部通过后才向首批测试用户发送公网 IP 和邀请码。

## 10. 后续升级为正式域名

购买域名并完成备案后：

1. 将域名解析到同一台服务器。
2. 在入口服务配置域名和自动 HTTPS。
3. 更新 Web 来源及安全 Cookie 配置。
4. 将 HTTP 请求永久跳转到 HTTPS。
5. 重新执行注册、登录、刷新令牌和管理后台验收。

PostgreSQL 数据卷、账号、邀请码、题库和学习记录保持不变，不需要迁移数据库。
