# 国内云内测部署、邀请码注册与题库导入设计

## 1. 背景

当前系统由 GitHub Pages 前端、Railway API 和 Railway PostgreSQL 组成。题库导入还需要在本地配置 `DATABASE_URL` 并运行命令。这套结构能够运行，但日常运营涉及多个平台、环境变量和命令行，不适合非技术管理员使用。

本设计面向第一批 10–20 名学生的封闭内测，将系统迁移至中国大陆云服务器，并把所有日常操作收敛到网站管理后台。

## 2. 目标与约束

### 2.1 目标

- 学生通过一个独立域名访问系统。
- 学生必须持有有效邀请码才能自行注册。
- 注册成功后自动登录并直接进入首次学习设置。
- 管理员可以在网站后台创建邀请码、管理学生和导入题库。
- 题库通过中文 Excel 模板导入，不再依赖命令行或数据库连接信息。
- 网站、API 和数据库集中部署，日常运营不需要操作 GitHub、服务器或数据库。
- 建立自动备份、监控、告警和可验证的恢复流程。

### 2.2 约束

- 第一阶段为 10–20 名学生的小规模封闭内测。
- 域名之外的服务器预算为每月 30–100 元。
- 采用中国大陆服务器，接受购买域名、实名认证和 ICP 备案。
- 继续使用现有 React、NestJS、Prisma 和 PostgreSQL 技术栈。
- 第一阶段不接入短信验证码、邮件验证码或在线支付。

### 2.3 非目标

- 不支持公开无限制注册。
- 不建设大规模多租户 SaaS 基础设施。
- 不在第一阶段拆分独立的数据库服务器、缓存集群或微服务。
- 不提供学生自行通过邮件找回密码。
- 不开发通用题库编辑器；题目批量维护以 Excel 导入为主。

## 3. 总体架构

### 3.1 部署结构

选择腾讯云中国大陆轻量应用服务器，初始规格为 2 核 CPU、2GB 内存和 40GB 系统盘。服务器使用 Docker Compose 管理以下服务：

1. **统一入口服务**：负责 HTTPS、域名访问、静态文件和反向代理。
2. **应用服务**：同时承载 React 构建产物和 NestJS API。
3. **PostgreSQL**：仅通过容器内部网络访问，不开放公网端口。
4. **备份任务**：每天生成数据库备份并上传至腾讯云对象存储。

```text
学生或管理员浏览器
        |
        | HTTPS
        v
独立域名与统一入口
        |
        +---- React 前端
        |
        +---- NestJS API
                  |
                  v
          PostgreSQL 私有网络
                  |
                  v
        定时备份与对象存储
```

前端和 API 使用同一个域名，消除跨域配置和多平台入口。公网只开放 HTTP/HTTPS；数据库端口和容器管理端口不开放。

### 3.2 容量与升级

2 核 2GB 规格用于第一轮内测。应用和数据库配置内存限制，并启用合理的 PostgreSQL 连接池上限。如果出现持续内存压力、请求延迟或并发增长，优先原地升级为 2 核 4GB，而不是重构系统。

### 3.3 源码与发布

GitHub 继续作为源码仓库，但不承担面向学生的站点入口。主分支通过受控发布流程更新服务器：

1. 自动运行测试和构建。
2. 构建通过后发布新容器版本。
3. 运行数据库迁移。
4. 启动新版本并检查健康状态。
5. 健康检查失败则恢复到上一可用应用版本。

数据库迁移必须保持向后兼容，应用回滚不自动回滚已成功执行的数据库迁移。

## 4. 域名、备案与上线

### 4.1 一次性上线流程

1. 在腾讯云注册可备案域名并完成实名认证。
2. 购买中国大陆轻量应用服务器。
3. 提交 ICP 备案；备案完成前仅进行内部测试，不向学生公开。
4. 部署统一入口、应用、数据库和备份任务。
5. 备案完成后将域名解析至服务器并启用 HTTPS。
6. 创建首个管理员账号。
7. 导入首批题库并生成邀请码。
8. 使用全新学生账号完成端到端验收。
9. 验收通过后向学生发送正式域名和邀请码。

### 4.2 费用边界

- 服务器以每月约 45–50 元的入门规格起步。
- 域名按年购买，费用取决于具体名称和后缀。
- 数据库备份占用少量对象存储，设置容量与费用告警。
- 当月预计总运行费用接近 100 元时发送预算告警，由管理员决定清理备份、限制资源或升级预算。

## 5. 邀请码注册

### 5.1 学生流程

```text
打开域名
  -> 输入邀请码
  -> 填写姓名、邮箱、密码和确认密码
  -> 创建学生账号
  -> 自动建立登录会话
  -> 进入首次学习设置
  -> 进入今日任务
```

姓名、邮箱和密码沿用现有注册字段。邮箱在系统内唯一，但第一阶段不要求邮件验证。密码继续采用安全哈希保存，任何页面和日志都不得记录明文密码。

### 5.2 邀请码模型

邀请码记录至少包含：

- 唯一标识和不可预测的邀请码。
- 管理员可读的批次名称或备注。
- 创建人和创建时间。
- 生效时间与过期时间。
- 最大使用次数和已成功使用次数。
- 状态：启用、停用、已过期、已用尽。

邀请码使用记录包含邀请码、注册用户和使用时间，便于追踪每名学生的邀请来源。

### 5.3 注册一致性

邀请码校验、账号创建和邀请码次数增加必须在一个数据库事务中完成：

- 账号创建失败时不消耗邀请码。
- 同一邀请码并发注册时不得超过最大使用次数。
- 邮箱已存在时返回明确提示，不创建账号。
- 已停用、已过期或已用尽的邀请码拒绝注册。
- 注册成功后立即创建学生会话。

### 5.4 管理后台

管理员可以：

- 单个或批量生成邀请码。
- 设置批次备注、有效期和使用次数。
- 查看状态、已使用次数、剩余次数和注册学生。
- 立即停用尚未使用完的邀请码。
- 查看学生姓名、邮箱、注册时间和邀请来源。
- 停用或恢复学生账号。
- 为学生生成一次性临时密码。

停用账号时撤销其全部有效刷新令牌，使现有登录会话失效。学生使用临时密码登录后必须设置新密码。

教师和管理员不能通过公开注册页面创建，只能由管理员后台创建。

## 6. Excel 题库导入

### 6.1 操作流程

```text
下载模板
  -> 填写或整理题目
  -> 上传 .xlsx 或 .csv
  -> 自动校验
  -> 查看预览与错误
  -> 确认导入策略
  -> 执行导入
  -> 查看导入批次
```

上传与确认分为两个请求。上传阶段只解析和校验，不写入正式题库；确认阶段使用服务器生成的短期导入令牌，防止文件被替换或重复确认。

### 6.2 中文模板

模板至少包含以下列：

- 科目
- 章节
- 知识点
- 题型
- 难度
- 题干
- 选项 A
- 选项 B
- 选项 C
- 选项 D
- 正确答案
- 答案解析
- 来源
- 年份
- 建议答题时间（秒）

知识点使用中文名称或受控下拉选项，不要求管理员填写内部 ID。多个知识点使用统一分隔规则，并在模板说明页给出示例。

### 6.3 校验

系统检查：

- 必填列和必填单元格。
- 科目、章节、知识点之间的对应关系。
- 题型和难度是否属于允许值。
- 选择题的选项数量和正确答案。
- 年份和建议答题时间的有效范围。
- 题干、选项和解析的长度限制。
- 文件大小、行数和格式。
- 文件内重复题以及数据库中的疑似重复题。

错误结果必须显示行号、列名、原因和修改建议，并支持下载错误清单。单次导入最多 1000 道题。只要存在阻断性错误，整批数据都不写入正式题库。

### 6.4 预览与重复处理

校验通过后，预览页面显示：

- 总题数。
- 新增数量。
- 重复并跳过数量。
- 可更新数量。
- 按科目、章节、知识点、题型和难度统计的分布。
- 前若干道题目的完整预览。

重复题按“规范化题干 + 来源 + 年份”识别，默认跳过。管理员可以在确认页面选择“更新重复题”。

### 6.5 历史记录保护

- 未产生学生作答记录的重复题可以原地更新。
- 已产生学生作答记录的题目不得覆盖；系统创建新版本并停用旧版本。
- 旧版本不再进入新的练习抽题，但继续用于历史答题、错题和报告展示。
- 导入批次可以整体停用，停用不删除学生历史记录。

### 6.6 导入批次

每次确认导入生成批次记录，包含：

- 文件名、文件摘要和上传人。
- 上传、确认和完成时间。
- 导入策略。
- 新增、更新、跳过和失败数量。
- 批次状态和错误摘要。

同一文件摘要与相同策略的重复确认必须具有幂等性，避免网络重试造成重复导入。

## 7. 管理后台信息架构

管理员工作区新增三个入口：

1. **邀请码管理**：创建、批量生成、停用、查看使用情况。
2. **学生账号**：查询、停用、恢复、生成临时密码。
3. **题库管理**：下载模板、上传校验、预览确认、查看批次和停用题目。

另提供只读的“系统状态”页面，展示：

- 网站和 API 健康状态。
- 数据库连接状态。
- 最近一次成功备份时间。
- 最近一次发布版本和时间。
- 磁盘使用率与关键告警。

系统状态页面不得展示数据库密码、访问密钥、令牌或完整错误堆栈。

## 8. 安全、日志与错误处理

### 8.1 安全

- 生产环境关闭演示登录。
- 管理员接口必须同时验证登录身份和管理员角色。
- 登录、注册、邀请码校验、题库上传和密码重置设置频率限制。
- 文件上传仅接受允许的扩展名和 MIME 类型，并限制文件大小。
- 导入文件存放在临时隔离目录，处理完成或过期后自动删除。
- 管理入口使用强密码；首个管理员通过服务器端一次性命令创建。
- 生产密钥只存储在服务器环境变量或密钥文件中，不提交 Git。

### 8.2 审计日志

以下操作写入审计日志：

- 邀请码创建、停用和使用。
- 学生账号停用、恢复和临时密码生成。
- 题库上传、确认导入、更新和批次停用。
- 管理员和教师账号创建。
- 发布、备份和恢复操作。

日志记录操作人、时间、动作、目标、结果和请求编号，但不记录密码、完整邀请码、令牌或上传题目全文。

### 8.3 用户可见错误

- 注册错误使用清晰中文提示，不暴露数据库或服务器细节。
- 导入错误精确定位到文件行列。
- 网络中断后允许重新查看未过期的导入预览。
- 重复确认导入返回原批次结果。
- 系统异常时展示请求编号，管理员可用该编号查询日志。

## 9. 备份、监控与恢复

### 9.1 备份策略

- 每天生成 PostgreSQL 逻辑备份并上传腾讯云对象存储。
- 对象存储保留最近 30 天的数据库备份。
- 每周创建服务器快照。
- 备份文件加密，访问密钥采用最小权限。
- 备份任务失败立即发送告警。

### 9.2 监控

监控项包括：

- 域名首页和 API 健康检查。
- 应用错误率与响应时间。
- CPU、内存、磁盘空间和容器状态。
- PostgreSQL 可连接性。
- 最近一次成功备份时间。
- 月度资源费用。

告警发送至管理员邮箱和腾讯云通知渠道。磁盘空间、备份时效和月度费用设置提前预警阈值。

### 9.3 恢复

每月至少在隔离环境执行一次恢复演练：

1. 创建临时 PostgreSQL 实例或容器。
2. 恢复最新备份。
3. 校验用户、题库、作答记录和导入批次数量。
4. 启动应用并完成登录与抽题检查。
5. 删除演练环境并记录结果。

生产恢复必须由管理员明确确认，且恢复前先保留当前数据库快照。

## 10. 测试与验收

### 10.1 自动化测试

- 邀请码状态、有效期、次数和并发使用单元测试。
- 注册事务、重复邮箱、账号停用和令牌撤销集成测试。
- Excel/CSV 解析、字段校验、重复识别和幂等性测试。
- 已作答题目的版本保护测试。
- 管理员权限和普通学生越权访问测试。
- PostgreSQL 迁移、备份和恢复冒烟测试。
- 发布健康检查和失败回滚测试。

### 10.2 端到端验收

上线前使用全新数据完成：

1. 管理员生成邀请码。
2. 新学生用邀请码注册并自动登录。
3. 学生完成首次设置、今日任务和一次答题。
4. 管理员上传包含正确、错误和重复数据的测试表格。
5. 系统正确阻止错误批次，正确预览并导入有效批次。
6. 学生能够抽取新导入题目。
7. 管理员停用学生账号，现有会话立即失效。
8. 数据库备份后在隔离环境成功恢复。
9. 手机和桌面浏览器完成关键流程。
10. 服务器重启后所有服务自动恢复。

### 10.3 完成标准

- 学生只通过一个域名完成注册、登录和学习。
- 无有效邀请码无法注册。
- 管理员不使用命令行即可完成邀请和题库导入。
- 数据库不暴露公网，生产环境关闭演示认证。
- 每日备份、每周快照、监控和告警均已启用。
- 已完成一次可验证的恢复演练。
- 中文操作手册覆盖备案、后台操作、题库模板、常见错误和故障处理。

## 11. 交付物

- 腾讯云部署配置与自动发布流程。
- 数据库迁移与新增数据模型。
- 邀请码注册和后台管理页面。
- 学生账号管理与临时密码流程。
- Excel/CSV 模板、解析、校验、预览和导入功能。
- 题目版本与导入批次管理。
- 自动备份、监控、告警和恢复脚本。
- 中文上线清单与管理员操作手册。

## 12. 实施顺序

1. 完成邀请码与账号状态的数据模型和后端规则。
2. 完成邀请码注册与管理员账号管理界面。
3. 完成题库导入模型、解析校验和幂等导入。
4. 完成题库管理界面和中文模板。
5. 完成单服务器 Docker Compose、统一域名和 HTTPS。
6. 完成备份、监控、告警和恢复演练。
7. 购买域名、提交备案并执行上线验收。

域名备案可以与应用功能开发并行进行，但学生公开访问必须等待备案完成。
