# Retrieval V2-40 Gold Workload Amendment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the active 100-question V2 Gold workload with an isolated, deterministic 40-question descendant, migrate only valid human-confirmed labels, and stop at a 28-question Human Gold Gate.

**Architecture:** A new `sampleV2Forty.js` module owns reduction, manifest validation, and the sealed 32/8 split without altering V2R2-100 behavior. The shared Gold core gains a third parameterized runtime, while the existing author CLI gains a `v2-40` mode and a one-purpose preparation command creates only gitignored local artifacts. Existing V1 and V2R2-100 APIs and artifacts remain backward-compatible and immutable.

**Tech Stack:** Node 24 ESM, `node:test`, `node:crypto`, existing canonical JSON hashing, existing Gold authoring CLI and local JSON artifacts.

## Global Constraints

- Parent sample is exactly `gold-sample-v2r2` SHA `be4485afd48a9107be3cfc63e896047911b642f95d013a649b7e17d8638109d4`.
- New lineage is `gold-sample-v2r2-40` / `gold-set-v2r2-40` / `gold-truth-v2r2-40`.
- Selection is status-blind and reads no Gold labels, old split, question text, retriever output, embeddings, or metrics.
- Per subject: 10 questions, KP `3/3/2/2`, difficulty `4/4/2`; global total 40.
- Split: DEV32/HOLDOUT8, 8/2 per subject; HOLDOUT difficulty `3/3/2`; two distinct difficulties and KPs per subject.
- Only human-confirmed source labels may migrate mechanically after fingerprint/node validation.
- V1, rejected V2/V2R, accepted V2R2-100, `gold-split-v2.json`, and `gold-set-v2.json` are never modified.
- No HOLDOUT ids are printed by the real preparation command.
- No AI-generated Gold; stop after local preparation at 12 confirmed / 0 draft / 28 unstarted.
- No automatic Git commit or push without explicit human authorization.
