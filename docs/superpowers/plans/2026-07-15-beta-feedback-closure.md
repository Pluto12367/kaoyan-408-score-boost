# 内测反馈闭环实施计划

## 目标

让首批内测学生能够提交真实、结构化且可追溯的体验反馈，并在提交前直接看到必要的隐私提示。生产环境反馈必须保存到 PostgreSQL，不能依赖通用 JSON 运行时状态。

## 任务 1：反馈数据契约与 PostgreSQL 持久化

- 先扩展 PostgreSQL 集成测试，验证：有效反馈写入独立数据表；无效评分、过短内容和不支持的场景返回 400；客户端不能覆盖官方问卷地址；管理员只能通过受保护接口读取反馈；API 重启后记录仍存在。
- 在 Prisma 中增加 `FeedbackSubmission`，关联提交用户，保存评分、场景、正文、处理状态和时间戳。
- 增加反馈 Repository；数据库模式只读取/写入 PostgreSQL，开发无数据库模式可保留内存实现。
- 服务端统一校验：评分为 1-5 整数；场景属于 `diagnostic`、`today_plan`、`practice`、`mistakes`、`exam`、`overall`；正文去除首尾空格后为 10-1000 字符。
- 问卷地址由服务端常量提供，不接受客户端传入值。

## 任务 2：真实学生反馈表单与隐私提示

- 先为纯反馈草稿校验函数增加失败测试，再实现共享校验。
- 将 `FeedbackPanel` 从固定演示提交按钮改为真实表单：场景、1-5 分评分、10-1000 字反馈正文。
- 表单展示字符计数、提交中状态、成功后清空正文，错误时保留输入以便重试。
- 提交前明确提示不要填写身份证、准考证、账号密码和联系方式等敏感信息。
- 在面板中直接提供内测隐私摘要，并保留腾讯问卷入口。
- `App.tsx` 只负责把表单值提交给 API，不再包含固定演示反馈。

## 验收

- 学生可以提交自己填写的真实反馈。
- 无效输入前后端都拒绝。
- 管理员反馈列表展示真实记录。
- API 重启后反馈仍存在于 PostgreSQL。
- 32 项既有单元测试、扩展测试、API/Web 构建和 PostgreSQL 集成测试全部通过。
