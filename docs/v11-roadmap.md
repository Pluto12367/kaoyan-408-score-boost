## 1. Mission Statement

**最大化学生有限备考时间转化为 408 考试分数。**

系统必须持续回答六问（六指标契约，继承自 LE §0.1）：

1. 学生当前水平？（mastery 轨迹 + 150 分估算）
2. 哪些已掌握 / 假掌握 / 正在遗忘？（mastery × stability × retention × 快照衰减）
3. 哪些最影响得分？（考频 × 分值 × 缺口）
4. 下一步学什么？（六因子推荐：考频×缺口×遗忘×练习科学×目标差×证据置信）

每项能力以**证据链**结算：行为 → Evidence → 能力变化 → 预测变化 → 分数提升。禁止伪造学习效果。

## 3. Acceptance Criteria（全局）

1. 交付：`git rev-list --count origin/feature/v3-product-refactor..HEAD == 0`（每次交付同步后）；生产 `/health` 200 且新能力端点 401 守卫生效。
2. 质量：全量 `npm test` 零新增失败；三端构建 PASS；新纯函数先 RED 后 GREEN。
3. 诚实：所有估算带"估算"+ 公式/来源；缺失数据显式缺席（null/未设置），禁止伪造 0。
4. 指标：每个 Feature 的 Acceptance 含六指标中至少一项的度量落地。
5. 边界：零 SoT 写触碰 / Mastery 公式与引擎排序零改动（触发暂停条件即停，等所有者）。

## 5. 长期方向（V11 之后，持续发现）

按 §六 自主发现机制持续审计：考前冲刺模式、院校目标分规划、错题根因分析、时间分配训练、高频陷阱识别——每一项立项前先过六指标门禁。知识图谱关系数据（B6）是内容侧最大短板，推动教研补录后 PREREQUISITE_GAP 推荐才能兑现。
