# Open-source reference check before coding

在本项目中，开始写业务代码、测试代码或脚本前，先做一次轻量的开源参考检查。

## 什么时候必须做

- 新增功能
- 修改现有行为
- 修复 bug
- 调整部署、导入、账号、权限、题库等关键流程

纯说明、现状汇报、只运行已有命令、只读检查，不需要执行这一步。

## 执行步骤

1. 用当前任务的关键词搜索 2-4 个相似开源项目、官方示例或成熟文档。
2. 记录可借鉴点：接口设计、数据模型、交互流程、边界条件、测试方式。
3. 明确不直接复制代码；只借鉴思路，并按本项目架构重写。
4. 如果没有找到合适参考，也要说明“未找到可直接借鉴的开源实现”，再继续编码。
5. 在最终交付或实现说明中简要写明参考了哪些方向。

## 推荐搜索范围

- GitHub 开源项目
- 框架官方示例和文档
- 成熟后台管理系统、认证系统、导入工具、学习平台的实现

## 交付时的说明模板

```text
编码前已做开源参考检查：
- 参考方向：
- 可借鉴点：
- 本项目采用方式：
```
